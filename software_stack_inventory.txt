VCSC SOFTWARE-STACK INVENTORY
=============================

Purpose
-------
This is the checked inventory for Immediate TODO step 6 in context.txt. It
records every compiler site that still emits a runtime `_pushN` allocation and
classifies why that storage exists. It is a snapshot of the transitional ABI,
not an endorsement of the software stack.

Snapshot
--------
Input archive:

    vcsc.20260716_224332.tar.gz

Compiler emission totals:

    5  `jsr _pushN` allocation sites
    13 `jsr _popN` emissions

The larger pop count is expected: the surviving legacy branches have normal
cleanup and several error-path cleanups.

Named automatic locals
----------------------
There are no remaining `_pushN` sites whose purpose is to allocate ordinary
named automatic locals. Named automatic locals and the hidden `$$` return
object use fixed-address symbols.

Do not confuse the compiler's host-side `ctx_push()` bookkeeping function with
the target runtime helper `_pushN`; they are unrelated despite the unfortunate
name collision.

Completed retained-language replacements
----------------------------------------
The following retained paths use fixed compiler-generated BSS scratch:

* direct-call argument evaluation and A:X capture;
* truth-value evaluation and discarded expression results;
* scalar/pointer comparisons and arithmetic;
* shifts, bitwise operations, multiplication, division, and remainder;
* casts and absolute-reference conversion;
* simple and compound assignments;
* built-in increment/decrement;
* switch expressions;
* local and return-object initialization;
* pointer/index lvalue calculation;
* bit-field read/write helper pointer preservation;
* braced assignments;
* runtime global initializers.

The compiler temporarily redirects `fp` to each fixed area, tracks the maximum
nested temporary depth, restores the caller `fp` through the 6502 hardware
stack, and copies results into the final destination. Scratch is currently
allocated per site and is not overlaid.

New scratch families in this revision include:

    __n65_indextmp_N
    __n65_bracedtmp_N
    __n65_globalinittmp_N

The bit-field helper paths no longer need scratch merely to preserve `ptr0`:
`_fp2ptr1p` only writes `ptr1`, so the destination/source frame pointer can be
prepared directly without disturbing the lvalue pointer in `ptr0`.

Non-emitting compiler consumers
-------------------------------
Helpers that manipulate `ctx->locals` and `(fp),y` temporary offsets without
emitting `_pushN` own no persistent function frame. Their bytes belong to an
enclosing fixed scratch area.

Runtime and generated-library dependencies
------------------------------------------
The target stack mechanism itself still lives in:

    libraries/nlib/asm/stack.asm       `_pushN` and `_popN`
    libraries/nlib/nlib_zeropage.s     `_nl_sp` and `_nl_fp`
    libraries/nlib/nlib.inc            `sp` and `fp` aliases
    libraries/nlib/nrt0.s              startup initialization

Additional obsolete dependency families include:

* `libraries/float/asm/*`, which uses `_pushN`/`_popN` extensively;
* `libraries/nlib/genasm.pl`, `gen_weakops.pl`, and `asm/weakops.asm`, which
  generate wide/general weak-operator helpers around the old stack ABI.

Recommended next slice
----------------------
Remove operator overloading, `$exactops`, weak built-in operator dispatch, and
their positive tests. Those are the only compiler paths that still emit
`_pushN` or `_popN`. After that, delete `_nl_sp`, `_pushN`, `_popN`, and the
software argument/local stack once no retained runtime or generated helper
requires them.
