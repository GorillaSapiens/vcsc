VCSC SOFTWARE-STACK INVENTORY
=============================

Purpose
-------
This checked inventory records target-runtime `_pushN` and `_popN` calls emitted
directly by compiler source. A regression test scans every compiler `.c` file and
fails if either helper reappears.

Snapshot
--------
Input archive:

    vcsc.20260716_232529.tar.gz

Compiler emission totals:

    0 `jsr _pushN` allocation sites
    0 `jsr _popN` emissions

Current compiler model
----------------------
Named parameters, automatic locals, return objects, call arguments, expression
temporaries, lvalue calculations, assignments, initializers, control-flow tests,
and switch expressions all use fixed-address symbols or function/depth-pooled BSS
scratch. The compiler may temporarily redirect `_nl_fp` to a pooled scratch symbol
and preserve the caller value with the 6502 hardware stack, but it no longer
allocates target data through `_nl_sp`.

Removed final emitters
----------------------
The final five `_pushN` sites and thirteen `_popN` emissions belonged only to:

* overloaded compound assignment;
* overloaded pre/post increment and decrement;
* weak built-in operator dispatch.

Operator overloading, `$exactops`, weak operator dispatch, their runtime generator,
and their positive tests have now been removed. Ordinary named-function overloading
remains supported.

Remaining runtime/library mechanism
-----------------------------------
The software-stack implementation itself still exists outside compiler code:

    libraries/nlib/asm/stack.asm       `_pushN` and `_popN`
    libraries/nlib/nlib_zeropage.s     `_nl_sp` and `_nl_fp`
    libraries/nlib/nlib.inc            `sp` and `fp` aliases
    libraries/nlib/nrt0.s              startup initialization

`_nl_fp` is still actively used as the base pointer for pooled scratch addressing.
`_nl_sp`, `_pushN`, and `_popN` survive only because obsolete runtime families—most
notably generic wide helpers—still reference them. They can be
removed after those unsupported type/runtime families are deleted.

Next slice
----------
Remove heap/`_sbrk` support, then give retained division a private fixed workspace
and delete `_nl_sp`, `_pushN`, `_popN`, and dead stack-pointer helpers. Keep
`_nl_fp` while compiler-generated pooled scratch still uses it.
