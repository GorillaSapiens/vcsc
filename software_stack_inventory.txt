VCSC SOFTWARE-STACK INVENTORY
=============================

Purpose
-------
This is the checked inventory for Immediate TODO step 6 in context.txt.  It
records every compiler site that still emits a runtime `_pushN` allocation and
classifies why that storage exists.  It is a snapshot of the transitional ABI,
not an endorsement of the software stack.

Snapshot
--------
Input archive:

    vcsc.20260716_172832.tar.gz

Compiler emission totals:

    30  `jsr _pushN` allocation sites
    78  `jsr _popN` emissions

The larger pop count is expected: most allocation sites have normal cleanup and
one or more error-path cleanups.

Named automatic locals
----------------------
There are no remaining `_pushN` sites whose purpose is to allocate ordinary
named automatic locals.  Named automatic locals and the hidden `$$` return
object already use fixed-address symbols.

Do not confuse the compiler's host-side `ctx_push()` bookkeeping function with
the target runtime helper `_pushN`; they are unrelated despite the unfortunate
name collision.

Compiler allocation sites
-------------------------

`compiler/compile_call.c` -- 2 allocations

1. `compile_indirect_call_expr_to_slot()`
   Classification: caller call frame; mostly obsolete indirect/variadic ABI.
   Contents can include the callee pointer, fixed stack parameters, a variadic
   byte blob and metadata, and scratch for an A:X result.  Zero-argument
   indirect calls are temporarily retained, but parameterized function
   pointers and varargs are already outside the intended final language.

2. `compile_call_expr_to_slot()`
   Classification: retained direct-call argument/result scratch plus obsolete
   variadic/legacy-stack branches.
   For the retained direct ABI this holds one reusable argument-conversion
   buffer and, when needed, caller-private memory used to consume A:X.  This is
   the first high-value call path to convert to fixed per-function scratch.

2. General truth-value evaluation buffer.
   Classification: retained scalar expression scratch.

3. Two-operand comparison buffer.
   Classification: retained scalar comparison scratch; float branches are
   obsolete.

4. Discarded expression-result buffer used by expression statements.
   Classification: retained scalar expression scratch.

5. Simple assignment conversion buffer for fixed symbols.
   Classification: retained scalar expression scratch.

6. Simple assignment buffer for indirect, absolute, or bit-field lvalues.
   Classification: retained lvalue/expression scratch.

7. Overloaded compound-assignment result buffer.
   Classification: obsolete operator-overloading support.

8. Overloaded compound-assignment conversion buffer for symbol destinations.
   Classification: obsolete operator-overloading support.

9. Overloaded compound-assignment conversion buffer for indirect lvalues.
   Classification: obsolete operator-overloading support.

10. Built-in compound-assignment working area.
    Classification: retained 8/16-bit expression scratch; float, wide-integer,

Non-emitting compiler consumers
-------------------------------
Several helpers in `compiler/compile_function.c` manipulate `ctx->locals` and
address `(fp),y` scratch without emitting their own `_pushN`.  Their storage is
owned by the surrounding function frame or expression allocation.  The notable
cases are `va_start`, `va_arg`, and `va_end`, all obsolete variadic support.

Runtime and generated-library dependencies
------------------------------------------
The target stack mechanism itself lives in:

    libraries/nlib/asm/stack.asm       `_pushN` and `_popN`
    libraries/nlib/nlib_zeropage.s     `_nl_sp` and `_nl_fp`
    libraries/nlib/nlib.inc            `sp` and `fp` aliases
    libraries/nlib/nrt0.s              startup initialization

Large additional dependency families are already outside the final language:

* `libraries/float/asm/*` uses `_pushN`/`_popN` extensively.
* `libraries/nlib/genasm.pl`, `gen_weakops.pl`, and `asm/weakops.asm` generate
  wide/general arithmetic helpers around the old stack ABI.
* `libraries/nlib/stdarg.n` and variadic compiler paths depend on stack-backed
  argument blobs.

Disposition and implementation order
------------------------------------

A. Remove first, because the feature itself is unwanted:

   * variadic functions and stdarg machinery;
   * parameterized indirect calls and likely all function pointers;
   * operator overloading and weak built-in operator calls;
   * float, wide-integer, and arbitrary-endian branches;
   * bit-field or aggregate-only scratch if those features are later rejected.

B. Replace for the retained language:

   * direct-call argument conversion and A:X consumption;
   * scalar truth/comparison/binary/shift/cast scratch;
   * pointer arithmetic and indexing scratch;
   * simple/compound assignment scratch;
   * switch-expression scratch;
   * scalar runtime initializer and return-object scratch.

C. Replace conditionally, after language-surface decisions:

   * aggregate/braced initializer scratch;
   * bit-field scratch;
   * absolute-reference scratch;
   * runtime global initializers.

Recommended next slice
----------------------
Introduce fixed-address per-function scratch symbols and convert the retained
**direct-call** path first:

1. reserve a function-qualified argument-conversion buffer sized to the largest
   fixed parameter used at any direct call in the function;
2. reserve a two-byte function-qualified A:X consumption buffer;
3. make `compile_call_expr_to_slot()` use those symbols instead of `_pushN`;
4. leave indirect/variadic calls on the old path temporarily, clearly isolated;
5. add code-generation and execution tests proving nested direct calls do not
   use `_pushN` merely to pass or consume scalar arguments/results.

This removes the ABI-facing stack use before attacking the much larger generic
expression engine.
