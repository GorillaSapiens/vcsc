all_five_player_color_181 ROM optimization - WORK IN PROGRESS
==============================================================

Status
------

This is an experimental post-item-23 optimization of the completed
all_five_player_color_181 renderer.  The last known-good baseline is the tree
from vcsc.20260811_093852.tar.gz.  Roadmap item 23 itself remains complete.

DO NOT treat the renderer in this handoff as functional.  The collapsed steady
loop is substantially smaller and mostly cycle-correct, but the 16-line row
transition is unfinished.  The current renderer does not yet produce the
required exact 262-line frame and has not passed final Stella equivalence.

Why this optimization exists
----------------------------

The known-good score-above 181-line example used 4048/4090 ROM bytes, leaving
only 42 bytes free.  Measurement showed that the score was not the main cause:
the unrolled combined renderer duplicated fourteen A/B pair bodies and was the
large ROM consumer.

The optimization removes that duplication.  The intended compact structure is:

  pair 1                    special
  pairs 2 through 6         one shared loop
  pair 7                    special packed-final-bit pair
  row-boundary handoff      special and STILL UNFINISHED

Measured WIP result
-------------------

Before optimization, score-above example:

  ROM: 4048 / 4090
  RAM:  107 / 128

Current collapsed-loop WIP, before the final cleanup/package of this handoff:

  ROM: 2624 / 4090
  RAM:  107 / 128

This recovers 1424 ROM bytes and leaves about 1466 bytes free.  The ROM collapse
is therefore worth preserving even though the row handoff is not finished.

What is working
---------------

* The fourteen duplicated A/B steady pair bodies have been removed.
* The old .align 256 padding in this raster was removed; it was not required by
  the timing annotations and cost roughly 112 bytes in the score-above image.
* The compact steady pair loop is cycle-scheduled against the known-good 181
  renderer rather than merely preserving total pair length.
* Shared pairs 2 through 6 were traced against the known-good raster and match
  the proven beam-critical playfield phases through the steady part of a row.
* Pair 7 was retimed after removing a duplicate row-base restore and is intended
  to match the known-good final-pair phases.
* RAM usage is unchanged.

Important bug fixed during the collapse
---------------------------------------

An early compact-loop version accidentally did this in effect:

  CPY player1_height
  LSR m0_mask
  ...
  BCC p1_active

LSR overwrote the carry produced by CPY.  On inactive P1 rows this could select
the active path, index the color table with a bogus Y value, and even introduce
an extra page-cross cycle.  The comparison is now established after the shift
so the later branch sees CPY's carry.  This was generated raster assembly, not
a compiler bug.

What is still broken
--------------------

The 16-line row transition is not yet compatible with the new single-cache
steady loop.

The original working renderer incrementally built an alternate seven-byte row
cache while drawing the current row.  The compact loop intentionally removed
that A/B cache construction.  At a row boundary the current WIP therefore does
not yet have all of the next row's PF bytes and M0 state prepared in the form
expected by the shared loop.

The first row can be made timing-correct, but subsequent rows enter late and/or
consume stale cache state.  The most recent CPU timing measurement was:

  expected frame CPU cycles: 20064
  current WIP CPU cycles:    20216
  excess:                      152 cycles = two 76-cycle scanlines

Therefore exact 262-line NTSC timing is NOT restored yet.

Recommended next implementation step
------------------------------------

Do not resurrect the fourteen-body A/B unroll.

Instead, make the row boundary feed the compact loop directly:

1. Render the first line/pair of the new row directly from ROM where practical.
2. Use one specialized transition pair to prime the four-byte live playfield
   cache plus the next M0 state.
3. Enter the existing shared pair-2-through-pair-6 loop at the same measured
   phase as row zero.
4. Keep pair 7 specialized for the packed eighth BL/M1/M0 bits.

The expected cost is roughly one extra specialized pair body, on the order of
100 bytes, not the approximately 1.4 KiB that was removed.

Timing invariants to preserve
-----------------------------

Use the known-good 181 renderer/listing as the oracle.  In particular:

* Normal reflected playfield handoff must retain the proven PF2/PF1 timing near
  cycles 48/55; preserving only the 152-cycle pair total is NOT sufficient.
* Player active/inactive paths must remain cycle-balanced.
* Nothing that changes carry may be inserted between CPY/CMP and a branch that
  consumes that comparison result.
* GRP1 timing must remain data-independent because writes to GRP1 transfer the
  delayed Ball latch while VDELBL is enabled.
* The terminal delayed-Ball zero must still be flushed before the blank tail so
  score-below composition does not inherit a one-line Ball artifact.

Acceptance before calling this optimization complete
-----------------------------------------------------

1. Exact 262-line NTSC frame for both score-above and score-below examples.
2. CPU/listing phase trace agrees with the proven 181 renderer at steady pairs,
   pair 7, every row boundary, and the terminal tail.
3. Stella full-raster comparison is pixel-for-pixel identical to the known-good
   181 renderer for equivalent solid player colors in BOTH score orders.
4. Verify P0/P1 per-row colors, P0/P1 graphics, M0, M1, Ball, asymmetric and
   reflected playfield, and the delayed-Ball boundary cases.
5. Re-run the 181 renderer regression and maintained Stella target.
6. Rebuild all public examples, staged installcheck, source-tree hygiene,
   assembly allowlist, and the normal test suite.
7. Update stale comments in all_five_player_color_181.c26 that still describe
   the former double A/B row-cache architecture.
8. Only after all of the above, update the documented ROM measurements for the
   two public 181 score examples.
