Current contract
----------------
* 192 visible NTSC lines, modeled as 96 two-scanline logical bands.
* Six eight-row logical sprites may use P0 or P1.
* Public X range is 0..159; public Y range is 0..95. Events whose setup would
  begin above the visible top are preloaded during VBLANK.
* The diagnostic playfield is 12 rows of 16 physical scanlines. It is dynamic,
  asymmetric, non-reflected PF0/PF1/PF2 data rather than a static symmetric
  backdrop.
* Per-event sprite colors are supported.
* Persistent fairness tracks every omitted sprite, then stable-partitions omitted
  IDs ahead of shown IDs for the next frame. Fairness must not be confused with
  avoidable scheduler omissions.
* Normal same-lane setup reservations are intentionally long: P0 15 logical
  bands, P1 12. Directional cross-lane setup hazards are real timing constraints.
  Do not weaken these constants globally to improve an allocator score.
* Same-X reuse is governed by a measured lane-independent raster invariant:
  if X is identical and |delta-Y| < 13, do not reuse that hardware player.
  This is separate from the ordinary full-position/setup reservations (P0 15,
  P1 12). P0 retained-X is available only at delta 13..14; P1 exact-delta-12
  ordinary reuse is allowed only when X differs. Try the other player first,
  then use persistent fair omission if neither lane is legal.
* The former equal-X delta-12 bridge orientation is intentionally retired. Its
  endpoints may no longer share P1 merely to avoid flicker; the maintained 7+5
  bridge witness now fair-flickers one of the three contenders and verifies
  complete glyph output for every scheduled sprite.
* P0 top-preload Y=89..91 has an extra predecessor state so P0/P1 first visible
  GRP lines match across Y=85..95. Re-run the lane-stability GRP oracle after any
  raster-state change.
* Current `VCS_NTSC_EXTENDED_VBLANK` TIM64T split is **63/13**. Preserve the
  total blanking budget and this split until a deterministic timing witness proves
  another division is safe.
* Hand-written conditional branches in this renderer require explicit timing
  contracts; do not introduce `.flex` conditionals into beam/deadline paths.

Current accounting and validation boundary
------------------------------------------
Current public accounting is 3993/4090 ROM and 115/128 RAM.

The same-X threshold change passes the focused real-6502 asymmetric test,
renderer branch-contract audit, source-tree hygiene, and history-format checks.
Broad validation is also clean: compiler 500/500 and E2E 319/319.  Because many
simulator tests deliberately run after printing their expected output, the E2E
pass used a temporary 2-second runner only to identify slow cases, then reran all
22 such cases with the repository's unchanged 45-second runner; all 22 passed.

Timing status
-------------
The obsolete delta-12 bridge oracle has been removed, reducing both ROM use and
VBLANK work. Its former dense same-column deadline state remains as a generic
scheduler timing regression.

Real Stella then exposed a separate 262/263 mechanism. With the 63/13 split, a
valid state X={14,0,25,88,114,140}, Y={76,67,95,95,95,95}, priority=
{2,3,4,5,0,1} returned from `vcs_ntsc_finish_deadline()` on scanline 52 at
horizontal CPU phase 72. The old `WSYNC := 0` materialized zero with a two-cycle
LDA before its STA; that pushed the TIA write across the 76-cycle boundary and
WSYNC then consumed another whole line. The host CPU harness still called the
frame 262 because its memory-write callback does not model this exact TIA
instruction phase, so real Stella is authoritative for this boundary.

The shared NTSC and PAL/SECAM 50 Hz scheduler cores now preserve A=0 by reading
INTIM into caller-clobbered X and use direct `STA WSYNC; STA VBLANK` at VBLANK
exit. An asserted TIMINT ($80) is normalized with ASL only on that already-late
path. Normal-path visible entry remains cycle 3. The 63/13 split is unchanged. In Stella 7 the witness now
passes 80/80 frames at 262, five other fixed stress scenes pass, and 384 held
real-Stella frames across 1/2/3/4/8/160-value X palettes with valid Y=0..95 all
reported 262. The maintained CPU test now also supports held ZP randomization and
exact pre-mutation failure dumps, and the asymmetric regression uses 16-frame
held dense-X layouts.

Allocator status
----------------
Production now enforces the measured same-X threshold in `ChooseLane`:

* identical X and |delta-Y| < 13 cannot reuse the same hardware player;
* P0's ordinary full-setup reservation remains 15 bands; retained P0 is used
  only for the measured-safe 13..14 same-X window;
* P1's ordinary full-setup reservation remains 12 bands, but exact delta 12
  reuses P1 only when X differs;
* rejected same-X reuse falls through to the other lane and then persistent
  fair omission.

Maintained real-6502 regressions pin the unsafe/safe boundary. A six-sprite
single-column delta-12 chain must avoid same-player reuse yet still renders all
six by alternating players; the corresponding delta-13 chain permits reuse.
Both require all eight exact glyph bytes for all six sprites. Historical delta-8
and delta-10 staggered witnesses still require fair flicker and byte-exact glyphs.

The host C scheduler remains the ordinary full-setup baseline oracle. Broader
allocator quality for other occupancy<=2 layouts is still unfinished. Do not
lower the 15/12 ordinary reservations or broad directional hazard windows.

Real-Stella allocator-quality witness: the interactive diagnostic can produce a
close staggered logical 2/5/0 cluster at distinct X positions where visible
occupancy never exceeds two sprites, yet the current scheduler fair-flickers the
cluster. The cause is not the same-X <13 rule: under the ordinary P0=15/P1=12
setup reservations, all three logical sprites conflict for the two hardware
lanes even though their visible glyph lifetimes do not form a three-way overlap.
Keep this 2/5/0 case as a concrete target for broader occupancy<=2 work. Any fix
should come from proving a tighter different-X handoff/setup schedule (or an
equivalent safe allocator capability), not by weakening the measured same-X
threshold or globally lowering the established 15/12 reservations.
