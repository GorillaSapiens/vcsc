VCSC MAIN ROADMAP
=================

Purpose
-------
This file contains only unfinished main-project work and its acceptance criteria.
Completed roadmap material is historical and belongs in
`.../context-history/`. The pre-cleanup full roadmap was archived in the
2026-08-22 history file.

Immediate TODO
--------------
The first unfinished item is the default main-roadmap action when the user has
not selected another workstream.

Current next action: Item 46, fix linker dummy-read hazards.

[ ] 46. Make the linker avoid destructive dummy/ghost reads.

        * Read `.../superchip_dummy_read_hazard.txt` before implementation; it
          contains the reproduced addresses, controls, root cause, and required
          generic linker model.
        * Treat mapper ranges where a CPU read has side effects as link-time
          hazards. Superchip `$F000-$F07F` (the RAM write port) is the first
          required hazardous-read range.
        * Model real NMOS 6502 intermediate bus cycles, beginning with absolute
          indexed page-cross reads whose uncorrected-high-byte dummy read can
          differ from the final architectural address. Keep the mechanism
          extensible to the other known indexed/dummy-access forms.
        * Analyze final relocated operands and mapper layout, not source-level
          intent. Conservatively consider the full index range when no narrower
          compiler/assembler range information exists.
        * Prefer placement constraints that move relocatable tables/sections so
          all possible intermediate reads are harmless while preserving the
          original instruction count and timing. Never fix this by silently
          inserting index-normalization instructions into beam-sensitive code.
        * If a fixed placement or other constraint makes a safe link impossible,
          emit a hard source-correlated error naming the instruction, encoded
          operand, hazardous dummy address/range, mapper hazard, and referenced
          symbol/section.
        * Add a minimal synthetic SC regression that reproduces the diagnostic's
          legal ROM lookup plus destructive page-cross ghost read, and prove the
          linker relocates a movable case safely and rejects an intentionally
          impossible fixed-placement case. Cover 4KSC/F8SC/F6SC/F4SC.
        * After the generic linker fix passes, move the diagnostic DETAIL1 row
          back to Superchip RAM and retain the original timing-sensitive wrapped
          reposition-table lookup. The P1 corruption must remain gone without a
          diagnostic-specific workaround.
        * Add a final-linked structural oracle that no indexed diagnostic access
          can dummy-read the SC write port, retain the hard P1 pixel oracle, then
          run the 12-case Stella matrix and complete suites.

[ ] 47. Add exhaustive Superchip RAM access regressions.

        * Treat the Superchip read/write split as a compiler and mapper contract:
          ordinary `cartram` source reads must use the `$F080-$F0FF` read alias
          and writes must use the corresponding `$F000-$F07F` write alias.
        * Exercise ordinary compiler-generated C26 accesses, not inline-assembly
          substitutes, so the tests cover the lowering that application code uses.
        * Cover scalar `cartram` objects plus arrays with constant-index and
          runtime-index reads and writes, including `x := sc[i]`, `sc[i] := x`,
          `dst[i] := src[i]`, and read-modify-write forms such as `sc[i] += 1`.
        * Include a small unmistakable pattern test (for example six bytes
          `11 22 33 44 55 66`, followed by a runtime-index overwrite/readback)
          so an alias or offset error identifies the exact failed byte.
        * Cover initialized Superchip DATA and zero-initialized BSS, and exercise
          the first, middle, and last usable bytes of the 128-byte SC region with
          sentinels so adjacent-byte corruption and off-by-$80 errors are caught.
        * Add structural compiler/linker assertions that final linked operands use
          the proper read alias for loads and write alias for stores, for both
          constant and runtime-index forms. This complements, but does not replace,
          execution tests.
        * Add simulator/emulator-backed execution checks that write through the SC
          write window, read the values back through the SC read window, compare
          against expected values, and prove neighboring bytes remain unchanged.
        * Run the same semantic access-pattern self-test under 4KSC, F8SC, F6SC,
          and F4SC. Integrate it into the existing FxSC bankswitching diagnostics
          so F8SC/F6SC/F4SC inherit it automatically, including their existing
          physical-start-bank coverage; give 4KSC equivalent dedicated coverage.
        * Keep a focused unit/regression test for the compiler-level `cartram`
          access contract even after the mapper diagnostics pass, so a future
          lowering regression fails without requiring a full diagnostic ROM run.
        * Keep this separate from Item 46: these tests certify intended direct SC
          accesses; Item 46 prevents unrelated CPU dummy reads from accidentally
          hitting side-effectful mapper addresses.

[ ] 48. Add optional paddle sampling to score renderers.

        * Allow paddle timing to continue through score scanlines instead of
          treating the whole score raster as an unsampled account_gap().
        * Support both two-paddle and four-paddle readers with deterministic,
          beam-safe sampling points chosen from each renderer's available cycles.
        * Preserve byte/pixel/timing-identical renderer output when paddle
          sampling is not requested.
        * Define the compile-time component contract rather than adding a
          runtime callback or other variable-cost mechanism.
        * Add timing and emulator-backed regressions that prove sampling cadence,
          paddle resolution, and unchanged score output across supported video
          standards.

[ ] 49. Add playfield-color support as an explicit renderer capability.

        * Define whether colors are global, per logical row, or both.
        * Schedule every COLUPF write against the beam.
        * Preserve existing renderer output when the feature is unused.
        * Expose a clear application data/API contract.
        * Add static, motion, transition, installation, and pixel/color-oracle
          coverage for every supported profile.

[ ] 50. Add a public side-scroller/platform example.

        * Demonstrate animated player sprites, horizontal world scrolling,
          platform/playfield collision, jumping/gravity, and camera/world-state
          separation.
        * Include at least one collectible, hazard, or goal and use original assets.
        * Stay inside a documented RAM/ROM/frame budget.
        * Add deterministic emulator-backed tests for scrolling, collision,
          animation, and completion/reset behavior.
