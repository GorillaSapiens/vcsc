VCSC MAIN ROADMAP
=================

Purpose
-------
This file contains only unfinished main-project work and its acceptance criteria.
Completed roadmap material is historical and belongs in
`.../context-history/`. The pre-cleanup full roadmap was archived in the
2026-08-22 history file.

Immediate TODO
--------------
The first unfinished item is the default main-roadmap action when the user has
not selected another workstream.

Current next action: Item 43, efficient startup for simple RAM setup.

[ ] 43. Efficient startup for simple RAM setup.

        * The compiler should accept only the `void main(void);` signature.
        * `main` is non-returning.  A fall-through/return from `main` must use
          `JMP ($FFFC)` rather than `RTS`; startup must enter `main` with `JMP`,
          not `JSR`, so no hardware-stack slot is wasted on an impossible return.
        * The linker should detect when the abbreviated startup is safe and select
          it automatically: no DATA copy, no runtime initializer work, and no
          cartridge-RAM initialization requirement beyond the simple RIOT-RAM
          clear handled by that startup.
        * Preserve the full startup for programs whose initialized data, runtime
          initializers, or mapper/cartridge RAM require it.
        * Add compiler/linker/startup regressions proving both automatic choices
          and the reset-vector fallback for an erroneous return from `main`.

[ ] 44. Add a public diagnostic cartridge that exercises and reports the supported
        console switches, controller types, TIA objects, playfield, colors,
        collisions, and audio.

        * Keep displayed results unambiguous.
        * Include deterministic self-test screens where practical.
        * Document required controller hookups and emulator configuration.
        * Verify every screen/mode with staged-toolchain and emulator-backed tests.

[ ] 45. Add playfield-color support as an explicit renderer capability.

        * Define whether colors are global, per logical row, or both.
        * Schedule every COLUPF write against the beam.
        * Preserve existing renderer output when the feature is unused.
        * Expose a clear application data/API contract.
        * Add static, motion, transition, installation, and pixel/color-oracle
          coverage for every supported profile.

[ ] 46. Add a public side-scroller/platform example.

        * Demonstrate animated player sprites, horizontal world scrolling,
          platform/playfield collision, jumping/gravity, and camera/world-state
          separation.
        * Include at least one collectible, hazard, or goal and use original assets.
        * Stay inside a documented RAM/ROM/frame budget.
        * Add deterministic emulator-backed tests for scrolling, collision,
          animation, and completion/reset behavior.
