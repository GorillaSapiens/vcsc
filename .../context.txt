VCSC PROJECT CONTEXT
====================

Purpose
-------
This is the small new-chat bootstrap for VCSC. Keep only durable rules, current
state that materially affects ongoing work, unfinished work, and the exact next
step. Completed narratives belong in `.../context-history/YYYY-MM-DD.txt`.

Read this file once near the start of a new chat. Do not reread it every turn.
Read a focused `.../*.txt` file only when the current task actually needs that
workstream. Never read `.../context-history/` wholesale; search/open only the
specific date needed for an older decision or regression.

Context budget
--------------
`.../context.txt` has a hard 16 KiB ceiling. Focused hot documents also have
small limits enforced by `test/source_tree_hygiene.pl`.

* Replace superseded current-state text; do not append another checkpoint.
* Put completed implementation detail, dated experiments, old measurements,
  failure transcripts, and superseded plans in the daily history file.
* Keep acceptance criteria only for unfinished work.
* Prefer executable regressions and maintained source documentation as durable
  truth instead of duplicating their details here.
* A completed focused roadmap may remain as a short durable closeout/tombstone,
  but not as a work diary.

History-entry policy
--------------------
Every meaningful completed change or decision goes in the local-date file
`.../context-history/YYYY-MM-DD.txt`. Entries are oldest first. Each entry starts
with exactly:

    YYYY-MM-DD HH:MM:SS PDT, short description

The description is mandatory, ASCII, at most 50 characters, and the complete
header is at most 72 characters. Continuation/detail lines are unrestricted.
Generate timestamps with:

    TZ=America/Vancouver date "+%Y-%m-%d %H:%M:%S %Z"

Source-lineage and workflow invariants
--------------------------------------
* The newest archive supplied by the user in the current chat is the sole source
  authority. Never silently merge it with a remembered tree from another chat.
* Do not develop the same VCSC lineage concurrently in multiple chats. If that
  happened, reconcile the divergent descendants explicitly before more work.
* Source archives have no wrapper directory; `COPYING`, `Makefile`, `compiler/`,
  `test/`, etc. are archive-root entries.
* Use top-level `make tar` for source handoff archives. Do not hand-roll the
  returned source tarball.
* Preserve `.../instruction.txt`; it is intentional project guidance.
* Use the term **renderer**, never **kernel**, for VCSC display implementations.
* Prefer targeted builds/tests while developing; run the broad suite at a real
  checkpoint or before handoff. Do not weaken a valid regression to make it pass.
* Before handoff: update only durable/open hot state, append completed work to
  daily history, clean generated residue, test, then package one latest tarball.

Project/toolchain invariants
----------------------------
VCSC is a deliberately constrained Atari VCS/2600 C-like compiler and companion
6502 toolchain. Current public tools are `vcsc`, `vcsc-cc1`, `vcsc-as`,
`vcsc-ld`, `vcsc-ar`, `vcsc-sim`, and `vcsc-disas`. Source is `.c26`, maintained
assembly is `.s26`, objects are `.o26`, and archives are `.l26`.

`compiler/ABI.txt` and the maintained public/internal component documentation are
the authorities for language, ABI, renderer timing, and cartridge contracts.
Do not re-copy those specifications into this handoff. Important general rules:
no software argument/local stack, no indirect calls/function pointers, static
non-reentrant activation storage, little-endian data, and explicit timing
annotations for beam-sensitive branches.

Open workstreams
----------------
1. **Enhanced asymmetric multisprite -- side quest**
   Read `.../enhanced_asymmetric.txt` when working on it. It is the sole enhanced
   multisprite implementation; the temporary symmetric prototype is retired.
   `lines` supports 192 (96 two-scanline bands, Y=0..95) and native PAL/SECAM
   228 (114 bands, Y=0..113). The 192 NTSC extended blanking split remains 63/13
   TIM64T. Preserve the measured same-X |delta-Y|<13 reuse prohibition and the
   ordinary P0=15/P1=12 setup reservations. See the focused hot file for the
   maintained scheduler invariants and next allocator-quality work.

2. **Main roadmap**
   `.../roadmap.txt` contains only unfinished main items. Default main-roadmap
   work begins with Item 47, the exhaustive direct Superchip RAM access suite.
   Item 46, the generic linker dummy/ghost-read hazard fix, is complete; its
   short durable contract remains in `.../superchip_dummy_read_hazard.txt` and
   executable regressions own the detailed behavior. Items 48-50 follow.
   Active workstream: `.../roadmap.txt`.

3. **Bankswitching**
   `.../bankswitching.txt` contains the durable cartridge model plus unfinished
   mapper diagnostics. Item 38 (F0/FA2/FC tier) is explicitly deferred until the
   user reopens it. Items 42-44 are diagnostic/profile backfills for FE/SCABS, WD, and DPC;
   FE/SCABS is the next open bankswitching item. 3F and classic 3E are complete;
   both public families route ordinary TIA I/O through the `$40-$7F` mirror so
   mapper-owned low-page writes cannot corrupt frame timing.

4. **Disassembler**
   `.../disassembler.txt` preserves the exact-round-trip contract and unfinished
   work only. Open items are GL, CM, DPC+, CDF-family support, remaining 6507
   interrupt-root cleanup, mapper-context abstract-state precision, fixed-point
   speculative validation, and ambiguous 2IN1 container handling.

5. **Zero static initializer placement**
   Mutable all-zero link-time static initializers are emitted directly as
   BSS/ZEROPAGE rather than DATA. This avoids pointless ROM copies and lets more
   programs select the compact startup. Const/readonly objects and pointer
   initializers that require backing objects retain their required storage
   semantics. Regression tests own the detailed placement/footprint expectations.

Human-readable linked listings
------------------------------
Final `.lst` sidecars now preserve C26/S26 source provenance through compile,
assemble, object, and link. Each source statement is followed by readable
generated 6502 assembly with final linked logical address and emitted bytes;
resolved 16-bit operands are shown so split-address mappings such as Superchip
read/write aliases are directly visible. Synthetic material is labeled rather
than assigned false provenance. Source metadata is transparent to peephole
optimization, and focused regressions lock source/assembly/address/byte
correlation plus an F8SC read/write-alias example. See `linker/README.md`.

Last validation state
---------------------
Main-roadmap Item 46 is complete. C26 `$read_hazard` and cfg
`read_hazard = yes` mark mapper ranges where CPU read bus cycles have side
effects; stock Superchip, FA/RAM Plus, and CommaVid write aliases are marked.
`vcsc-ld` models statically knowable NMOS 6502 reads/dummy reads from final
linked instruction bytes for all 256 opcode values, including unofficial raw
`opXX` handwritten assembly. Movable referenced layouts receive safe-placement
constraints; fixed unsafe instructions hard-error with source/assembly
provenance. Runtime-computed indirect effective addresses remain unknowable.

The diagnostic DETAIL1 row is restored to Superchip RAM. Its original wrapped
absolute,Y reposition-table lookup remains timing-identical; the linker places
`diagnostic_reposition_table` at `$F1F0`, so the wrapped operand is `$F100`
rather than the destructive `$F05D`. The final map keeps DETAIL1 at read `$F0CB`
/ write `$F04B`, and the structural regression proves the five indexed lookups
cannot dummy-read `$F000-$F07F`.

Validation after the fix: all 502 compile-phase tests pass. All 329 e2e tests
pass; the long suite was completed in ordered batches after the outer command
window interrupted the monolithic run. The optional Stella 7.0 diagnostic
oracle was re-blessed for all 12 NTSC/PAL/SECAM x controller cases in the
preceding validation pass; this closeout rechecked NTSC joystick/paddle/keypad
and driving against those references. Focused SC/FxSC/FA/CV and linker hazard
tests also pass after marking the legacy cfg RAM write aliases hazardous.
