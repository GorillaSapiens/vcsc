VCSC ITEM 31: SPECIALIZATION / INLINING ROADMAP
===============================================

Purpose
-------
Implement fixed-point whole-program specialization and profitable inlining for
reachable translation-unit-internal functions with exactly one ordinary direct
call site. Keep source-level `inline` semantics separate: this roadmap concerns
optimizer-selected specialization/inlining of ordinary functions.

Status legend: [ ] not started, [~] partial, [x] complete.

0. Single-callsite analysis foundation
--------------------------------------
[x] Record ordinary direct *call-site occurrences*, not only unique call-graph
    edges, and expose one authoritative query for whether a defined static
    function has exactly one ordinary direct call site. The analysis also retains
    the exact unique caller and call-expression AST node needed by later parameter
    specialization passes.
[x] Conservatively classify baseline eligibility: body present, static/internal,
    not source `inline`, and exactly one ordinary direct call site. Leave ABI,
    assembly-reference, placement, and profitability vetoes to later sections.
[x] Add compiler unit/codegen tests covering zero, one, and multiple call sites;
    two calls from the same caller count as two, while two distinct callees
    called once each both classify as single-callsite functions.
[x] Document implementation notes here before moving on.

1. Single-callsite ref-parameter address specialization
-------------------------------------------------------
[x] For regular, const, and writeonly `ref` formals at an eligible single call
    site, bind the formal directly to the known actual address when the actual is
    a compile-time-resolvable object/lvalue address. Do not allocate or copy a
    callee ref-address slot in that case.
[x] Rewrite loads/stores through the formal to the actual read/write address and
    preserve split-address semantics. Propagate fixed ref bindings to a fixed
    point through nonrecursive single-callsite ref chains.
[x] Re-run normal addressing-mode relaxation so zero-page actuals use compact
    instructions when legal.
[x] Unit tests: regular ref read/write, const ref read-only, writeonly ref stores,
    zero-page contraction, split read/write address handling, fixed members and
    constant indexes, fixed-point chains, mixed value/ref signatures, assembly
    vetoes, and a non-resolvable actual that must retain the ordinary ref slot.
[x] E2E RAM/map test proving the specialized ref slot disappears, including a
    matched mixed-signature case where specialization removes exactly two bytes.

2. Readonly by-value parameter specialization
---------------------------------------------
[x] Detect explicit const formals and implicit readonly formals whose value is
    never written and whose private by-value storage identity is not observable.
[x] Prove caller actual storage remains stable while the caller is suspended
    before aliasing the formal directly to caller storage. Otherwise retain the
    ordinary by-value copy. Current proof is intentionally conservative for
    globals, absolute objects, address escape, aliases, and type conversions.
[x] Run constant propagation/dead-code elimination after binding. The shared
    constant evaluator resolves specialized readonly formals inside supported pure
    arithmetic, comparison, logical, cast, and ternary expressions. Constant-bound
    `if`, `while`, `for`, `do`, and ternary control flow lowers only reachable
    paths, and reachability uses the same evaluator so dead call edges disappear.
    This item does not claim unrelated general unreachable-statement cleanup.
[x] Unit tests: explicit const, implicit readonly, callee write veto, write-through-
    call veto, address-observation veto, caller-storage escape/stability veto,
    same-object value/ref aliasing, type-conversion fallback, literal constants,
    and direct constant-bound `if` pruning.
[x] E2E RAM/map tests prove accepted cases remove formal storage and rejected cases
    preserve it, while simulation locks the by-value copy semantics of aliasing,
    mutable-global, address-observation, and conversion fallbacks.

3. Optimizer-selected IR/control-flow inlining
----------------------------------------------
[x] Implement the ordinary-function IR/control-flow expansion mechanism without
    source-text substitution or abusing source `inline`. It is currently reachable
    only through debug `-X inlineir`; production selection remains deliberately
    gated on subsections 4 and 5.
[x] Correctly rewrite/carry parameters, locals, return objects, labels, and every
    return edge, including ordinary copied parameters, multiple returns, and early
    returns.
[x] Simplify specialization-exposed expressions/control flow and recompute the
    effective callsite graph to fixed point. The authoritative census switches from
    lexical occurrences to reachable/enabled direct-call occurrences after DCE, so
    pruning one of two calls can expose a new single-callsite specialization. A
    unique-callsite inline only moves its nested call occurrences and cannot change
    their multiplicity; nested one-call chains already expand recursively, so a
    redundant post-inline lexical census is neither needed nor performed.
[x] Preserve activation/scratch lifetime semantics: optimizer-inlined bodies keep
    distinct activation owners and activation-only lifetime edges, so nonrecursive
    mutually exclusive lifetimes remain overlayable without inflating JSR depth.
[x] Unit/E2E tests: void/value returns, mutable copied parameters, multi-return
    control flow, nested one-call chains, locals/temporaries, sibling lifetime
    overlay, an ordinary call nested inside an inlined body, and hardware-stack
    depth reduction.

4. Placement/timing legality gate
---------------------------------
[x] Before accepting an optimizer inline, prove final linker placement can still
    satisfy every `.same`/`.cross` branch annotation and applicable alignment /
    page-containment constraint. The current proof is conservative: hard branch
    policy or hard function-page geometry on either side of the unique callsite
    retains the separate function rather than gambling on final placement.
[x] Keep independently placeable code/result-region contracts on either side of
    the callsite as a conservative veto until trial placement/rollback exists.
[x] Unit/E2E tests: `.same`/`.cross` retention and successful final placement,
    source-inline-transitive hard branch detection, hard page containment with a
    fixture that would exceed 256 bytes if expanded, function `align()` rejection,
    named code/result-region vetoes, and unconstrained/page-data success cases.

5. Profitability and fixed-point decision
-----------------------------------------
[x] Measure final linked ROM size and hardware-stack depth before/after a legal
    candidate. Accept when linked code improves without violating constraints;
    reject measured ROM growth. Stack-depth reduction is a secondary benefit.
[x] Recompute RIOT activation/scratch overlay after each accepted transform.
    Inlining itself must not be treated as an inherent RAM tradeoff; unexpected
    loss of an equivalent overlay is an allocator/lifetime-analysis bug.
[x] Unit/E2E tests: exact ROM win, exact ROM loss/rejection, stack-depth reduction,
    unchanged peak-RAM overlay, and fixed-point nested wins.

6. Reachability / ABI / assembly-boundary vetoes
------------------------------------------------
[x] Exclude exported functions, extern/ABI entries, source `inline` functions,
    contract/lifecycle hooks requiring identity, and any function whose address or
    independently callable symbol escapes through supported assembly mechanisms.
[x] Remove dead unreachable internal functions when safe after specialization and
    fixed-point call-graph recomputation. Runtime-global-initializer calls are
    explicit execution roots even though they have no ordinary function caller.
[x] Unit/E2E tests for every identity veto, runtime-initializer and assembly roots,
    post-specialization dead-call removal, and unreachable dead-function removal.

7. Integration, diagnostics, and documentation
----------------------------------------------
[x] Keep normal output stable. Existing debug-only analysis controls remain internal;
    `-finline-profit -v` is the supported concise measured accept/reject trace.
[x] Update driver/compiler README documentation for observable behavior only.
    Automatic parameter specialization is documented separately from the opt-in
    measured `-finline-profit` trial-link pass.
[x] Run compile-unit suite, focused E2E/map tests, full E2E behavior, examples build,
    source-tree hygiene, context-history format, branding, and install validation.
    The monolithic score-composition raster test exceeds this container's command
    window, so its four renderer families were run as four disjoint shards covering
    the same 40 public pairs, 32 production cartridges, 80 generated static/motion
    compositions, and mixed-instance checks.
[x] Record final ROM/RAM/stack deltas on representative maintained examples and
    close main roadmap item 31 only after all subsections above are complete.

2026-08-13: Subsection 0 complete. Added `compiler/compile_inline_analysis.c`
and `.h` as a small policy-neutral callsite fact store, plus
`compile_inline_prepass.c` and `.h` for a pre-lowering AST census. The census
runs after top-level function predeclaration and before any ordinary function
body is emitted, so later specialization passes can query the unique caller and
exact call-expression AST while lowering the callee itself.

Call occurrences are deliberately distinct from the existing deduplicated
caller/callee graph. Two calls from the same caller count as two sites. Source
`inline` function bodies are expanded by the census at each source-inline call
site rather than counted once lexically, so ordinary calls nested inside a
source-inline wrapper acquire the same multiplicity they will have after source
inline expansion. Invalid source-inline recursion is cycle-guarded in the census;
normal lowering remains responsible for the user diagnostic.

Compiler-facing wrappers expose count, unique caller, unique callsite, and
baseline-candidate queries. Baseline eligibility currently means defined +
static/internal + not source `inline` + exactly one ordinary direct callsite;
later subsections own the ABI, assembly, timing-placement, and profitability
vetoes. `-X inlineplan` is a debug-only trace used by regression tests to prove
that these facts already exist when a function definition begins lowering.

Tests: `inline_analysis_unit.pl` directly unit-tests the standalone fact store.
`inline_analysis_codegen_test.c26` exercises the real prepass, including zero,
one, repeated same-caller, sibling single-callsite, exported, source-inline, and
source-inline-expansion-multiplicity cases. Focused tests pass, and the complete
compile-side suite passes 475/475 after building all host tools.

2026-08-13: Subsection 1 complete. Added `compile_inline_specialize.c/.h`.
For an eligible static function with one direct callsite, regular, const, and
writeonly ref formals now bind directly to compile-time-fixed actual lvalues.
Accepted actuals currently include fixed globals, ordinary/zeropage locals,
absolute/split-address objects, struct members, constant-index array elements,
and already-specialized ref formals. Runtime-index lvalues and other unresolved
addresses retain the ordinary two-byte ref-address ABI slot.

Planning iterates to a fixed point. Thus `main -> middle(ref) -> leaf(ref)` can
bake the same caller address into both callees even when `leaf` appears first in
source. Split-address regular refs bake distinct read and write aliases directly;
the one-byte discarded increment/decrement fast path was generalized accordingly,
so `x++` can compile as a direct read from the read alias and direct store to the
write alias without pointer scratch. Zeropage fixed actuals relax to zeropage
opcodes after linking.

The ABI-changing transform is intentionally conservative at assembly boundaries.
For now, any candidate containing inline asm is vetoed, as is a function whose
callable source/assembler symbol is mentioned by inline asm elsewhere in the
translation unit. Subsection 6 remains responsible for replacing that broad
safety rule with a complete assembly-escape proof; this is deferred, not partially
implemented here.

ordinary/zeropage/split/member/index actuals, runtime-index fallback, fixed-point
propagation, mixed signatures, and both assembly vetoes. The E2E companion links
and simulates the accepted/fallback cases, checks final zero-page and split
opcodes, and proves map-level RAM behavior. A matched mixed-signature pair originally used
5 activation bytes when the ref was specialized versus 7 when a runtime-index ref
forced the old ABI. Subsection 2 subsequently removes two readonly literal value
slots from both sides, so the maintained expectation is now 3 versus 5; the ref
specialization still accounts for exactly the same two-byte difference. The compile-side

2026-08-13: Subsection 2 is mostly complete; general post-binding folding/DCE
remains partial. Eligible single-callsite ordinary value formals are now classified
readonly by scanning for direct writes, increment/decrement, address observation,
and ref-mediated exposure. Explicit `const` and inferred readonly formals share the
same storage-identity proof: `const` forbids direct writes but does not make the
private by-value address unobservable.

A readonly formal can bind directly to an exact-type caller object when that object
is stable while the caller is suspended. Mutable ordinary caller locals/parameters
are accepted only when their address never escapes; language-const symbol-backed
objects are intrinsically stable. Mutable globals, absolute/hardware-backed
objects, escaped addresses, same-object value+writable-ref calls, and actual/formal

constant actuals bind as values with no storage object. The constant is normalized
through the formal representation before later wider use, preserving the same
parameter-conversion semantics as the old copied slot.

Accepted bindings suppress the callee parameter allocation. Direct caller-storage
bindings load the known caller object; constant bindings emit immediates. A first
post-binding DCE case is implemented: when the specialized constant formal itself
is an `if` condition, only the reachable arm is lowered. General folding of larger
expressions containing the bound formal, ternary/loop pruning, and a reusable
post-binding expression/DCE pass remain explicitly partial under the third checkbox.

2026-08-13: Subsection 3's inlining mechanism is implemented and tested behind
the debug-only `-X inlineir` forcing switch. `compile_inline_inliner.c/.h` plans
mechanically safe baseline candidates for the transformation; normal production
compilation does not yet select optimizer inlines because placement/timing legality
and measured profitability belong to subsections 4 and 5. Source `inline` remains
a separate language feature even though both paths share the low-level AST/IR
control-flow expansion machinery.

Optimizer-selected bodies retain their ordinary function storage names, which is
important when subsection-2 readonly specialization has already baked a caller
formal symbol into a nested callee. Parameters that specialization cannot remove
are copied into the inlined callee activation normally. Locals, scratch, return
objects, and unique inline return labels lower through a fresh function context;
multiple/early returns jump to that expansion's return label. Nested pre-existing
single-callsite chains recursively disappear as standalone procedures even when
defined in reverse order. General post-transform callsite rediscovery and general
expression/DCE fixed-point simplification remain partial under the third checkbox.

Inlining originally assigned all expanded storage to the hardware caller, which
was semantically correct but destroyed legal sibling RAM overlay. This was fixed
with `__sbpmeta$I$caller$callee` activation-only lifetime metadata. The compiler
tracks the hardware call-graph function separately from the current activation
owner. The linker consumes ordinary E-edges plus I-edges only for activation RAM
layout; hardware-stack depth, bank placement, reachability, and CALL GRAPH output
continue to consume only real E/JSR edges. Thus an inlined body can keep a local
live across a non-inlined call without either RAM alias corruption or fake stack
depth. Calls used while evaluating later inline arguments are conservatively
nested under the inline activation as well.

2026-08-13: Subsection 5 complete behind the internal/opt-in profitability path.
The compiler can emit a per-translation-unit manifest of candidates which have
already passed the subsection-3 mechanical checks and subsection-4 placement
legality gate, and can recompile an explicitly selected candidate set. The
driver's `-finline-profit` development path performs silent speculative final
links through the real linker and accepts a candidate only after measuring the
resulting whole-image MEMORY USAGE. This is intentionally not the normal default
yet; subsection 6 still owns the remaining ABI/reachability/assembly-identity
vetoes required before production selection can be enabled.

The measured rule is monotonic: reject any trial that grows final cartridge ROM,
accept smaller ROM when activation/object RAM does not regress, and use reduced
hardware-stack reserve as a secondary win when ROM is exactly equal. Unexpected
activation/object RAM growth is treated as a lifetime/overlay bug rather than a
RAM-for-ROM trade. After each acceptance the driver keeps the accepted object,
relinks the whole program, and retries the original legal candidate set until no
further trial is accepted. General discovery of *new* single-callsite candidates
created by a transformation remains the separate partial subsection-3 census/DCE
work; subsection 5 reaches fixed point over the authoritative candidate set it was
given.

The first measured implementation exposed and fixed a real scratch-lifetime bug:
`compile_expanded_symbol_call()` reserved caller argument scratch whenever a call
had arguments even if every formal had already been specialized. Scratch is now
acquired lazily only for an argument which actually needs staging, restoring the
expected pre/post-inline activation overlay. It also exposed a subsection-2 fixed-
point corner: `main -> middle(4) -> leaf(x)` could first bind `leaf.x` to the soon-
to-disappear symbol `middle$x`. Value plans now have a revisioned fixed point and
upgrade an address-backed plan to the stronger propagated constant binding; the
natural nested constant chain links without any artificial mutable-formal escape.

`inline_profit_metrics_unit.pl` locks final-map parsing and the ROM/RAM/stack
decision matrix. `optimizer_inline_profit_e2e.pl` links and simulates normal and
measured forms. `leaf` plus `middle` are both accepted for an exact 8-byte final
ROM win, unchanged activation/object RAM, and reduced hardware stack. A legal
six-return `loss` candidate measures larger when expanded (the inline return jumps
outweigh JSR/RTS removal), so the same run rejects it and retains its standalone
function despite the potential stack reduction. This supplies a real final-link
ROM-loss oracle rather than only a synthetic cost estimate.

2026-08-13: Subsection 6 complete. Added `compile_inline_identity.c/.h` as the
shared ABI/assembly/reachability policy layer used by both parameter specialization
and ordinary-function inlining. Exported/non-static definitions, source `inline`,
merged `require`/`recommend` function contracts, functions containing inline asm,
and functions whose callable or ABI-family symbol is mentioned by source assembly
retain identity. ABI-family scanning deliberately treats `name$...` (including
parameter/return symbols) as an escape, so specialization cannot silently remove
storage which assembly may name. VCSC currently rejects language-level function
pointers, so inline assembly is the supported callable/address escape mechanism.

Reachability now uses the authoritative direct-call occurrence graph. Non-static
definitions, `main`, merged contract functions, and assembly-escaped functions are
roots. Calls emitted by runtime file-scope initializers are recorded as rootless
execution-root calls: their callees remain reachable and are not ordinary inline
candidates because there is no source-function AST caller to expand into. After
ref/value specialization reaches its fixed point, reachability is recomputed and
the already-implemented direct constant-bound `if` pruning disables call edges in
discarded arms. Unreachable static compiler-owned bodies can then be omitted. Dead
call cycles are conservatively retained so the existing recursion diagnostic is not
hidden; functions containing inline asm are also retained because opaque asm may
define externally consumed labels/exports.

The public driver still performs an unpruned compile+assemble validation pass before
using the dead-pruned image for `-finline-profit`, so dead stripping cannot hide
source or assembler diagnostics. `optimizer_inline_identity.pl` covers the identity
veto matrix, including a merged contract and `function$parameter` assembly escape.
`optimizer_inline_reachability_e2e.pl` simulates post-specialization dead-call
removal, ordinary dead chains, exported/contract/assembly roots, an opaque-asm body,
and a runtime-global-initializer-only helper, and proves a dead invalid-assembly body
still fails validation. `inline_analysis_unit.pl` directly covers reachability-edge
enable/disable, runtime-root calls, and cycle retention.
