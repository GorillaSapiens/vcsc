VCSC RENDERER / STRIPES ROADMAP
================================

Goal
----
Add compile-time PF/color stripes to `all_five`, then the remaining maintained
renderers, zero path.

Stripe ABI
----------
Add `parameter stripes := 0;`; zero preserves the old path with no arrays.
`stripes:=N` requires `game_playfield_colors[N*2]` and
`game_playfield_data[N*6]` (`TEMPLATE_playfield_colors/data`). Store COLUPF/COLUBK
then left/right PF0/PF1/PF2; stripe i owns
`floor(i*L/N)..floor((i+1)*L/N)-1`. Preserve raster/timing/handoffs/resources/write
phases; no runtime division or per-line feature test.

Positive stripes preserve the maintained frame, handoff, resource, branch,
object, phase, composition, zero-path, and pinned-palette Stella contracts.
192/228 remain terminal-WSYNC; 170/181 retain score-composable handoffs.
Measurements and discarded prototypes belong in tests or daily history.

Steps
-----
Completed: 192-line `stripes:=1/2`, A/B buffers, all tail handlers, runtime
dispatch, six-line PF refill, zero-path/resource/height/branch/handoff/motion
contracts, and Stella RGB are green. No third cache or stripe-count RAM is used;
canonical PF0 source bytes keep their low nibble zero for the hidden enable
baseline. Future public renderer name: `gameplay`; rename waits for stable ABI.

Remaining:

1. Promote the now-emitted combined refill/row-edge cadence into the normal
   stripes=2 path. `stripe_pair_machine_search.pl` remains the sole visible
   cadence authority: one 152-cycle epoch runs from physical A:02 through the
   following A:01 and all modes share the same 17 TIA appointments.

   The emitted tail-0 certification now performs the real three-pair inactive-PF
   refill (all six PF bytes plus both next colors), then later crosses packed-row
   edges without changing PF phases or the P0/P1/M0/M1/Ball value sequence. Row
   edges precompute one exact next-row P0 byte into each of six otherwise-dead
   stride-four mask bytes. The pair-7 B side carries that byte in Y across the
   right-PF writes, then `TYA + LSR M0 + INX + backedge` fits the existing
   16-cycle P0 tail; the M0 shift stays last among flag-changing data operations
   so its carry reaches the following ENAM0 write.

   The three exact refill P0 bytes are moved out of +35/+39/+43 before the
   row-edge cache overwrites that lane: two use the reclaimed P0 service-pointer
   bytes and the third uses the reclaimed low P1 service-pointer byte after the
   exact-P1 builder is finished. Thus the combined path is back to the normal
   98-byte RAM footprint with no temporary player/refill array. Next remove the
   probe-only switches and make this identical-cadence path production. Do not
   restore the older 20-byte row-entry table, a six-byte player cache, or a
   separately timed service row. `stripe_pair_exact_search.pl` and
   `stripe_three_pair_exact_search.pl` remain compatibility shims only.
2. The generic service geometry now has an executable bound.  The raw
   PF/color copy is three pairs / six scanlines, but the existing zero-tax
   dual-uniform dispatch needs five ordinary-entry candidates.  Exhaustive
   uint8 player-state search proves no legal ordinary-entry candidate set fits
   inside 13 pairs; starts 1,3,5,9,11 always fit inside 14 pairs.  Therefore
   28 scanlines is the current implementation-safe generic stripe-height
   target.  A row-boundary-capable start-8 dispatch would tighten this to
   13 pairs / 26 scanlines (starts 1,3,5,8,10), but that dispatch is not yet
   implemented.  For 192 lines the 28-line bound permits equal stripes=1..6;
   stripes=7 first becomes geometrically possible at the 26-line target.
   `stripe_min_height_bound.pl` owns these bounds.  Do not expose 28 as the
   public ABI minimum until the service-pointer preparation/loading path is
   emitted; six lines remains only the copy lower bound.
3. Generalize the double-buffer scheduler to N > 2, beginning with the
   28-line/at-most-six-stripe geometry above, and add asymmetric N=3 and N=5
   fixtures.  The first implementation may keep the stricter 28-line bound;
   optimize row-boundary entry toward 26 only after generic handoff works.
4. Add programmer-supplied height tables; reject odd heights, incorrect sums,
   and heights below the measured minimum. Never silently round.
5. Certify every maintained line mode, including non-divisible 228 and the
   181/170 score-composable handoffs.
6. Exercise all supported missile/player-color combinations.
7. Add a public example and documentation for geometry, storage, costs,
   composition, even-height rules, minimum-height rules, and the chosen
   `gameplay` name/API migration.
8. Add and certify stripes in `multisprite`.
9. Add and certify stripes in `enhanced_multisprite_asymmetric` for 192/228.
10. Close roadmap item 57 once obsolete renderers are gone and the normal suite
    is clean.
