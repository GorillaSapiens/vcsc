VCSC RENDERER / STRIPES ROADMAP
================================

Goal
----
Add compile-time playfield/color stripes to the consolidated `all_five`
renderer, then to `multisprite` and `enhanced_multisprite_asymmetric`, while
preserving the retired-renderer behavioral coverage and zero-stripe path.

Stripe ABI
----------
Add `parameter stripes := 0;`; zero preserves the old path with no arrays.
`stripes:=N` requires `game_playfield_colors[N*2]` and
`game_playfield_data[N*6]` (`TEMPLATE_playfield_colors/data`). Store COLUPF/COLUBK
then left/right PF0/PF1/PF2; stripe i owns
`floor(i*L/N)..floor((i+1)*L/N)-1`. Preserve raster/timing/handoffs/resources/write
phases; no runtime division or per-line feature test.

The 192-line S12 probe measured the current all-five steady playfield writes at
PF1/PF2 25/32 or 26/33 and reflected PF2/PF1 48/55; row boundaries use
22/29 then 45/48. A maintained full-asymmetric renderer proves six-write phase
families PF0/PF1/PF2 7/14/21 + 40/47/54 and 13/20/27 + 46/53/60. Positive
stripes therefore need a real six-write reschedule, not two inserted PF0 stores.
A six-byte zero-page PF cache costs 36 cycles/scanline versus the old four
absolute load/store pairs at 28, so the 192 all-five visible body must reclaim
8 cycles per scanline. For N=3 the public stripe payload is 24 ROM bytes versus
the old 48-byte playfield; an eight-byte data/color cache is the useful prototype
shape, with draw-dead object-mask scratch as a zero-extra-RAM overlay candidate.

Renderer constraints
--------------------
Full-height 228/192 schedules enter draw at cycle 3, return at 0 with terminal
WSYNC, no entry HMOVE/successor, and VBLANK <=1800. Score-composable 181/170
uses one entry HMOVE plus successor. Preserve the maintained `vcs_all_five_*`,
`vcs_player_color_*`, combined-color, pairwise-position, composition, TIA-phase,
object, and pinned-palette Stella coverage while adding stripes.
