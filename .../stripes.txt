VCSC RENDERER / STRIPES ROADMAP
================================

Goal
----
Add compile-time PF/color stripes to `all_five`, then the remaining maintained
renderers, zero path.

Stripe ABI
----------
Add `parameter stripes := 0;`; zero preserves the old path with no arrays.
`stripes:=N` requires `game_playfield_colors[N*2]` and
`game_playfield_data[N*6]` (`TEMPLATE_playfield_colors/data`). Store COLUPF/COLUBK
then left/right PF0/PF1/PF2; stripe i owns
`floor(i*L/N)..floor((i+1)*L/N)-1`. Preserve raster/timing/handoffs/resources/write
phases; no runtime division or per-line feature test.

Do not lock the positive-stripe storage ABI yet.  An 8-byte row-major record
`[COLUPF,COLUBK,PF0L,PF1L,PF2L,PF0R,PF1R,PF2R]` remains a good authoring form,
but `stripe32_record_common_index_bound.pl` rejects it as the hot common-index
source: the two legal >=7-cycle copy windows/pair are already consumed by PF.
The raster instead uses three 96-byte phase feeds proved by
`stripe32_feed_layout.pl`: feed0=C0/C1/PF4, feed1=PF0/PF2/PF5,
feed2=PF1/PF3/unused.  Y=95..0 indexes players and all feeds with fixed 4-cycle
abs,Y loads; the hot representation is 288 bytes and needs no stripe index.
If records become public ABI, derive the feeds at build time.

Positive stripes preserve the maintained frame, handoff, resource, branch,
object, phase, composition, zero-path, and pinned-palette Stella contracts.
192/228 remain terminal-WSYNC; 170/181 retain score-composable handoffs.
Measurements and discarded prototypes belong in tests or daily history.

Steps
-----
Completed: 192-line `stripes:=1/2`, A/B buffers, all tail handlers, runtime
dispatch, six-line PF refill, zero-path/resource/height/branch/handoff/motion
contracts, and Stella RGB are green. No third cache or stripe-count RAM is used;
canonical PF0 source bytes keep their low nibble zero for the hidden enable
baseline. Future public renderer name: `gameplay`; rename waits for stable ABI.

Remaining:

1. Make the six-scanline rolling machine the production positive-stripe
   architecture, with `stripes:=32` as the zero-slack design point.
   `stripe32_sixline_machine_search.pl` is now the timing proof: three exact
   152-cycle pairs copy all six inactive PF bytes plus both arbitrary next
   colors, feed both players through three-byte service pointers, leave the
   public player Y values untouched, and preserve all 51 ordinary TIA
   appointments.  There is no service row and no alternate PF phase family.
   The emitted stripes=2 refill/compact-rowedge probes remain useful source
   material but must converge onto this one cadence rather than grow another
   scheduler.

2. Use one frame-wide player index, not per-stripe pointer motion.
   `stripe32_common_index_search.pl` keeps all 51 TIA appointments with Y=95..0;
   active pointers change only at real activity/wrap transitions.
   `stripe32_transition_cache_bound.pl` proves <=2 special stripes/player, <=4
   union, <=12 exact player bytes.  Exact-cache reads raise a special stripe's
   prep budget from 17 to 29 cycles: exactly 24 for both 16-bit pointer copies
   plus 5 for control.  Aggregate cost closes; fragmented-slot packing/event
   selection is the remaining handoff problem.  Do not restore per-pair height
   tests or per-stripe -3 pointer updates.  Keep the 97-byte zero source optional
   until emitted 4K ROM cost is measured.

3. The old 28/26-scanline result is not a stripe-height limit.  It bounds only
   the discarded strategy that searched ahead for a convenient common uniform
   window; its executable proof is retained as
   `stripe_dual_uniform_window_bound.pl`.  The active design target is six
   scanlines.  Do not describe 28 or 26 as a public minimum again.

4. Emit the rolling machine in `all_five.c26`, first behind a focused probe,
   then remove the stripes=2-only production machinery.  Preserve the 4K ROM,
   <=128-byte RAM, frame, PF phase, complete object-sequence, handoff, and
   pinned-palette Stella contracts.  Saving/restoring SP around visible drawing
   is allowed if the emitted form uses TSX as the packed-row-X shadow; there are
   no stack accesses inside the raster.

5. Promote the public 192-line example to `stripes:=32`.  The intended data is
   already checked in as `examples/_common/all_five_stripes32_rainbow_data.c26`:
   32 six-line bands, dark rainbow COLUBK values, and bright COLUPF values eight
   Atari hue steps away (complementary hue), over a visible alternating PF
   pattern.  Keep the current two-stripe example runnable until the renderer
   itself accepts 32; do not ship a deliberately non-building public target.

6. After 32 works, generalize compile-time storage/geometry to every supported
   `stripes:=N` with minimum height six scanlines.  Equal 192-line stripes then
   support N=1..32; non-divisible counts use explicit/programmer-supplied even
   height tables whose sum is 192.  Reject odd heights, incorrect sums, and
   heights below the measured minimum; never silently round.

7. Certify every maintained line mode, including non-divisible 228 and the
   181/170 score-composable handoffs; exercise all supported missile/player-color
   combinations; document storage, costs, composition, and the eventual
   `gameplay` name/API migration.

8. Add and certify stripes in `multisprite`, then
   `enhanced_multisprite_asymmetric`; close roadmap item 57 only when obsolete
   renderer paths are gone and the normal suite is clean.
