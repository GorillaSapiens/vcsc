2026-09-11 00:19:52 PDT, fix F0 vs 8IN1 inference
Investigated supplied corpus image b65d4a38d6047735824ee99684f3515e.bin,
which VCSC classified as 8IN1 while Stella classified it as F0. The 64K image
contains one direct STA $FFF0 switch stub in every one of its 16 physical 4K
banks. Forced F0 analysis observes 17 decoded hotspot accesses and exact
round-trip reconstruction succeeds.

The root cause was that VCSC's raw F0 detector accepted only the private VCSC
"F0" tail signature. Without that marker the whole 64K image could remain RAW,
after which the outer-container detector found eight independently plausible
8K slices and promoted the file to 8IN1. Extended the F0 raw detector to accept
repeated direct accesses to $1FF0/$FFF0 using STA, LDA, BIT, or absolute NOP;
two such occurrences are required. This provides positive CPU-visible F0
evidence without copying Stella's blanket otherwise-unknown-64K => F0 fallback,
which would hide unsupported 64K mapper families behind a false F0 result.

Added paired synthetic regressions. f0_vs_8in1.bin deliberately has eight
independently executable 8K slices but replicated direct F0 switch stubs; the
untouched prior tree calls it 8IN1 and the corrected tree calls it F0.
multicart_8in1.bin is a genuine eight-game 64K container with no F0 hotspot
evidence and remains 8IN1, guarding against an over-broad 64K/F0 heuristic.
Both fixtures exact-roundtrip in the focused disassembler regression.

Reworked detached speculative-island discovery from a JAM-anywhere rejection
heuristic into edge/path viability. JAM/KIL/HLT kills only that speculative
continuation; conditional branches survive when at least one feasible successor
is live, while all-dead successors reject backward. Abstract flag facts prune
known-impossible branch arms, and JSR requires both the callee and return
continuation to remain viable.

transfers into non-executable TIA/RIOT hardware space are dead, while RIOT RAM
remains a possible copied-code target. Candidate opcode evidence now
separates official, stable unofficial, unstable unofficial, and JAM classes.
TIA/RIOT accesses use hardware read/write decode; canonical spellings score
more strongly than legal mirrors, and physically invalid accesses are dead.
Known mapper hotspots override generic hardware scoring only in the directions
the mapper actually uses. WD regressions pin the read-hotspot exception and
reject the corresponding write.
