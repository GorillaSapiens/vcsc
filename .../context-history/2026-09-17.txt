2026-09-17 08:29:00 PDT, safe compact TIA startup normalization
---------------------------------------------------------------
The earlier all-register `$00-$2C` startup sweep was too broad because it strobed
beam/control registers. A temporary sparse inert-register replacement avoided
those strobes but cost 17 ROM bytes and still omitted VDELP0/VDELP1/VDELBL, which
let randomized delayed graphics leak into Stella output.

Replaced that checkpoint with a nine-byte descending `$04-$2C` sweep in all three
stock startups and the faithful/enhanced private startup bodies. This deliberately
leaves VSYNC/VBLANK/WSYNC/RSYNC (`$00-$03`) untouched. In descending order HMCLR
is written immediately before HMOVE, so HMOVE applies zero motion, while graphics
and enables are already cleared before the RESP/RESM/RESBL position strobes are
reached. VDEL state, audio, playfield, colors, motion, enables, and collisions are
also normalized. The DATA startup reuses the sweep's zero A value for its RIOT
clear, removing a redundant `lda #0`; its net cost versus the pre-normalization
DATA startup is seven bytes. Full startup cases that cannot use the blanket DATA
path pay the full nine-byte sweep cost.

Updated startup-selection byte contracts, linked-image/ROM-accounting fixtures,
and frame-timing expectations where the deliberate startup AUDV0=0 write is now
observable. The animated-gallery authoritative JSON was remeasured only for the
seven-byte ROM delta; RAM/layout contracts are unchanged.

Focused validation: `vcs_startup_tia_stella.pl` passes with Stella developer TIA
randomization for simple, DATA, and full stock startups; the previously failing
HEART_LINES=0 pinned Stella raster again matches exactly. The heart examples build
again without overflow. The original size/timing regressions checked so far pass,
including E0/F0/FC 262-line timing, all-five player-color 181/192, multisprite
profiles, 170-line dual score, six-glyph wide/big-wide, banked standard renderer,
three-plus-three score, faithful legacy multisprite, linker page containment/image
model, and example-build shard 6/8.

2026-09-17 10:40:22 PDT, safe universal TIA mirror startup
----------------------------------------------------------
The compact startup TIA normalization now writes `$44-$6C`, the `$40` mirror of
TIA `$04-$2C`, in all stock and private startup bodies. This preserves the nine-
byte descending loop and its HMCLR-before-HMOVE ordering while avoiding mapper-
owned low-page addresses. The supported mapper audit found no hotspot in
`$40-$6C`: 3E/3F reserve low writes through `$3F`, WD uses low reads `$30-$3F`,
and the other supported selectors live elsewhere. The mirror is therefore the
safe universal startup form rather than a mapper-specific exception.

This fixes a concrete 3F/3E bug in the prior `$04-$2C` form. On those cartridges
the low-page stores were mapper operations instead of ordinary TIA writes, so
random power-on audio state could survive; that explains the reported horrible
3F/3F-max sound. `vcs_startup_selection.pl` now locks the `$44` byte sequence,
and `vcs_3f_3e.pl` additionally requires the safe mirror sequence while rejecting
the old low-page sequence. Stella randomized-TIA startup certification and 3F/3E
random-bank/random-TIA certification pass.

The reported manual mapper failures also exposed stale example binaries. The
automated mapper tests build fresh ROMs in temporary directories, but the public
bankswitching example Makefiles previously depended mostly on local diagnostic
sources. A prior `.bin` could therefore survive runtime, linker, compiler,
assembler, or mapper-library changes and `make play` would launch it unchanged.
The 3E, 3E-max, 3EX-max, E0, F0, FE, 3F, and 3F-max Makefiles now track the
relevant built tools, runtime archive, and mapper sources; 3EX-max preserves its
separate compile/link dependency structure. A new regression locks this build-
dependency contract.

Fresh focused certification passes for E0, F0, FE, 3E-max, and 3F-max in addition
to 3F/3E. Fresh manual Stella launches of 3E-max and 3F-max reached their normal
WAIT displays under bank/TIA randomization. The exhaustive 3EX-max regression ran
past the local execution window; its maintained documentation already records the
independent Stella 3EX >64K RAM-offset truncation bug, so no VCSC behavior was
weakened to accommodate that emulator defect. Faithful-legacy multisprite jitter
was explicitly deferred until this mapper/startup work is settled. The compile-only
suite is clean at 583/583 after the new regression, and source-tree hygiene passes.
2026-09-17 11:02:27 PDT, name TIA $40 write mirror
`vcsc-disas` now gives the conventional TIA $40-$6C write-register mirror
explicit `MIRROR_*` equates instead of spelling those operands as base-page
symbols plus `$0040`.  Direct `$49` therefore emits `MIRROR_COLUBK`, and
presentation-only indexed naming lets the stock startup pattern `STA $44,X`
emit `STA MIRROR_NUSIZ0,X` without teaching mapper/evidence analysis to assume
an unknown X/Y selects one fixed TIA register.  Other mirrors such as `$0109`
retain the existing `COLUBK + $0100` form.  `$6D-$6F` remain numeric because
there are no writable TIA registers $2D-$2F.

`disassembler/README.md` documents the convention.  The hardware fixture covers
direct, indexed, and explicitly-wide indexed forms; its generated source
round-trips byte-for-byte through `vcsc-as`.  `vcsc-disas` builds cleanly with
`-Werror`.  The monolithic `vcsc_disassembler.pl` regression exceeded a 120 s
single-command execution window before reaching its final summary; no failure
was used to justify or weaken this change.

2026-09-17 11:13:32 PDT, simplify TIA mirror spelling
The short-lived MIRROR_* alias scheme is superseded. vcsc-disas now uses the
canonical TIA/RIOT register symbol plus the actual mirror offset, so $49 emits
COLUBK + $40 and startup-style $44,X emits NUSIZ0 + $40,X. Higher mirrors
retain the same convention, e.g. COLUBK + $0100. Offsets through $ff use two
hex digits; larger offsets retain four. Indexed $40-page naming remains a
presentation-only aid and does not strengthen mapper/evidence assumptions.
