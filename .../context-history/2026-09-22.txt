Measured the existing 192 all-five PF write phases directly from a built ROM:
steady patterns are PF1/PF2 25/32 or 26/33 with reflected PF2/PF1 48/55; row
boundaries use 22/29 then 45/48. A scratch CPU trace of the maintained enhanced
asymmetric renderer provides known-good six-write families PF0/PF1/PF2 at
7/14/21 + 40/47/54 and 13/20/27 + 46/53/60.

This exposes the S12 implementation budget. Full stripe data needs six PF writes
per scanline. A six-byte zero-page cache needs 36 cycles for six load/store pairs,
versus 28 cycles for the current four absolute playfield pairs: S13 must recover
8 cycles per scanline rather than simply inserting PF0 writes. For stripes=3 the
public payload is 6 color bytes + 18 playfield bytes = 24 ROM bytes, half the old
48-byte 192-line packed playfield before code/cache overhead. Eight object-mask
bytes are draw-dead after VBLANK (3,7,23,27,31,35,39,47), making an eight-byte
stripe data/color cache a zero-extra-RAM overlay candidate; offset 47 is only safe
if positive-stripe mode retires the old playfield-position restoration contract.
The cache reload strategy across stripe boundaries remains an S13 design task.
