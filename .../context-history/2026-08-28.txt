2026-08-28 10:25:15 PDT, P1 staging supersedes RESP theory
The earlier 08:39 RESP0-phase closeout is superseded. User testing showed the
P1 corruption still present, and the surrounding six-glyph rows made a
cross-frame TIA-state explanation implausible. The TIA panel P0 positioning was
returned to its original x=32 behavior.

Fresh Stella launches of the same bad cartridge produced several different P1
rasters. Hardcoding DETAIL1 pair indices was stable, and normal font pointer
lookup using fixed indices was stable. Private collision workspace, a dedicated
Superchip reader, and direct assembly stores to the Superchip row did not fix
it. Moving only the six live DETAIL1 pair indices from Superchip cartridge RAM
to ordinary RIOT RAM produced 12/12 stable fresh Stella boots. This isolates the
active problem to live DETAIL1 cartridge-RAM staging/readback rather than the
font tables, pointer lookup tables, or six-glyph renderer.

The current source adds `diagnostic_detail1_row[6]` in ordinary RAM plus a
dedicated `diagnostic_prepare_detail1_row()` pointer-expansion path. A leading
WSYNC explicitly preserves the scanline consumed by the former generic prepare
path. The Stella regression keeps a hard dark-rectangle oracle on the corrupt P1
trailing area before masking the live controller rows.

Focused tests currently pass: vcs_diagnostic_cartridge.pl, vcsc_branding.pl,
source_tree_hygiene.pl, and context_history_format.pl. The 12-case Stella matrix
and full 327-test suite still need rerunning before this is certified.
