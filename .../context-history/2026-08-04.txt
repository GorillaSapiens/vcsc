2026-08-04 02:07:16 PDT, add Superchip-backed automatic locals
----------------------------------------------------------------
* Complete detailed bankswitching roadmap item 13. Automatic local scalars,
  arrays, structures, packed bitfields, and inline-expansion-private locals may
  select a split-address writable region such as `superchip` while retaining
  VCSC's fixed non-reentrant activation-storage model.
* Preserve region identity plus read/write aliases on local context entries and
  lvalues. Reads use the read alias; assignments, declaration initializers,
  compound operations, increments/decrements, and indexed writes use the write
  alias. Existing alias-aware lowering handles ordinary operations.
* Replace the former split-bitfield-write rejection with a two-alias sequence:
  evaluate the destination once, load the physical storage through its read
  alias, edit a compiler scratch copy, and store through the write alias. An
  arbitrary explicit split ref still requires a known constant alias delta for
  this generated operation.
* Emit split automatic storage in per-function
  `BSS.<region>.__vcsc_activation$<owner>` layouts, including private inline
  locals. Fix activation BSS zero records so startup initialization targets a
  split region's write window rather than its read-only window. Physical bytes
  remain region-local activation-overlay storage and are counted once.
* Add compile-only regressions for local declarations, direct/runtime indexing,
  inline locals, alias-aware packed-bitfield writes, and the deliberate
  function-scope-static restriction. Add `superchip_locals.pl`, which runs
  F8SC/F6SC/F4SC from every physical startup bank and verifies initializers,
  compounds, increments, bitfields, inline expansion, repeated nested
  cross-bank calls, exact eleven-byte map occupancy, read/write alias coherence,
  and deterministic overflow.
* Update compiler ABI/storage documentation, linker activation documentation,
  VCS Superchip usage documentation, detailed roadmap status, and source-tree
  hygiene. Roadmap item 14, Superchip-backed value parameters, is next.

  tests pass in ordered chunks, including every new Superchip-local execution

2026-08-04 03:48:33 PDT, add generic startup-main placement and split value parameters
---------------------------------------------------------------------------------------
* Remove the compiler's spelling-based `bank0` rule for `main`. In a banked
  configuration, unqualified `main` is now pinned by `vcsc-ld` to the unique
  BANKS entry marked `startup=yes`, using that bank's ordinary allocatable ROM
  MEMORY region. An explicitly qualified `main` is accepted only when its
  MEMORY region belongs to the same startup bank; diagnostics report the actual
  configured region and bank names.
* Generalize mapper-table validation so logical bank names are labels rather
  than required BANK0/BANK1 tokens. Physical file order and selector hotspots
  remain derived from logical start addresses and mapper rules. Public profiles
  retain their conventional BANK0 startup names without making those spellings
  semantic.
* Complete bankswitching roadmap item 14. Any split-address writable `mem`
  region may back a value parameter. The parameter remains an exact-sized,
  callee-owned symbol in its region-local activation layout. Callers evaluate
  and convert all arguments left-to-right into scratch, then copy split
  parameters through their write aliases immediately before JSR. Callee loads
  use read aliases and callee stores use write aliases; inline parameters use
  the same generic lowering.
* Extend same-translation-unit function signatures with parameter region
  identity and linker-visible ABI metadata with that identity plus read and
  write starts. Declarations and definitions cannot silently disagree about
  split storage. Keep split-address `ref` parameters rejected because the

* Add `linker_startup_main_generic.pl`, using PEAR/BANANA logical banks and
  `pear_code`/`orange_code` MEMORY regions. Its ordinary CODE fallback is the
  non-startup bank, proving plain `main` follows `startup=yes`; it also proves

* Update compiler ABI/language documentation, linker placement and activation

2026-08-04 08:16:42 PDT, make direct-call argument staging selective
-----------------------------------------------------
* Replace whole-list direct-call staging with a generic liveness rule. Argument
  expressions still evaluate left-to-right, but a converted value is copied to
  its callee-owned parameter object immediately unless a later argument may
  execute a function call. Only values which must survive such a later call
  remain in caller-owned scratch until all evaluations finish.
* Keep one reusable conversion slot for the largest unstaged argument and place
  preserved arguments before it in the same caller scratch lease. Call-free
  lists therefore reserve the maximum argument width rather than the sum of all
  widths; nested-call sites reserve only the crossing values plus that reusable
  slot. Split-address parameters use the same generic immediate/delayed decision
  and always copy through their configured write expression.
* Treat ordinary and inline call expressions conservatively as possible runtime
  calls; exclude compile-time compiler builtins and unevaluated sizeof operands.
  This preserves sibling activation overlay safety, including self-target nested
  calls, without hard-coding parameter regions or mapper names.
* Add call_selective_staging.pl. It proves a 1+2+1+4-byte call-free list uses a
  four-byte reusable slot, a nested-call list stages only the first byte plus
  that four-byte slot, and a call in the first argument needs no preserved
  prefix. Update call-order expectations, compiler/ABI, VCS, test, and detailed
  bankswitching-roadmap documentation.
* Verification: all 357 compile-only tests pass. All 221 end-to-end/generic
  tests pass; the long suite was completed in ordered continuation chunks after
  the execution timeout, with source-tree hygiene rerun after removing the
  temporary resume helper. Focused call-order, selective-staging, sibling-
  overlay, Superchip-parameter, and generic split-parameter tests pass. Staged

  binding. Installed TIA, RIOT, and Superchip headers, examples, tests, and

  local objects, functions, and aggregate members. Absolute bindings reject
  initializers, `static`, `extern`, `page`, named `mem` placement, use
  contracts, and `@[none/none]` while preserving either one-sided `none`.

  inline-assembly uses continue to consume the lvalue's independent read and
  write expressions; no code recognizes a hardware-register name, the spelling
  `superchip`, window order, adjacency, or distance.
* Compare same-translation-unit redeclarations by canonical address value, so
  equivalent numeric spellings agree. Emit linker-visible global ABI metadata
