2026-09-15 00:35:43 PDT, plan Direct Register Access
Documented the proposed C26 Direct Register Access facility in `.../DRA.txt`
without changing compiler behavior. The design uses `$A/$X/$Y` for direct
physical-register access, narrowly exposes `$S` through TSX/TXS, uses direct
condition tests for branchable `$C/$Z/$N/$V`, and permits only native
single-instruction writes for C/I/D/V. `$P` is deliberately not an ordinary
pseudo-register because whole-status access requires visible stack/A effects.
There will be no `$_`: explicit discard uses `(void) expression`. The old
lone `_` remains unchanged for now and is planned for hard migration to `$A`
or `(void)` only after DRA codegen exists. The implementation roadmap is split
into twelve focused slices sized for one short execution window each; DRA1 is
lexer/parser/AST scaffolding and rejection tests only.
