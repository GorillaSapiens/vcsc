2026-09-05 10:43:00 PDT, incremental C26 bloat autopsy
Started the Tanks asm-to-C26 cleanup by translating only `tanks_move_object()`
and measuring the generated 6502 after each compiler change. The first naive
translation looked much larger, but the algorithm itself was not the cause.
General compiler/codegen gaps accounted for the waste: runtime-indexed byte
truth tests fell through generic scratch/pointer lowering; direct byte-array
`++`/`--` missed indexed INC/DEC; direct scalar indexes were needlessly loaded
through A before TAX/TAY; direct RAM array reads preferred Y even though the
6502 has compact zero-page,X LDA and no zero-page,Y LDA; matching indexed
INC/DEC arms reloaded the same runtime index; and `!A || B` used an avoidable
branch/JMP bridge. Counted loops now mark X as live so the new direct-array fast
paths do not clobber an X-backed induction variable.

Added/updated focused compile regressions for runtime-indexed byte truth tests,
indexed byte updates/conditional updates, and compact table lookup inside
X-backed counted loops. The full compile-only suite is now 504/504 passing.
`tanks_move_object()` is now ordinary readable C26 and links at exactly $56
bytes (86 bytes), the same size as the handwritten asm block it replaced. The
whole cartridge therefore remains 4046/4090 ROM and 121/128 RAM. The deliberate
asm reduction repins Tanks to 320 reviewed asm statements / digest
57b2aef4fddf8c3e5a6e5f296dffcf4fe1f75db1812ebccd592d3904490015ca.

Unfinished discovery: `tanks_random()` is the next small specimen. A clean C26
LFSR spelling measured 22 bytes versus the current 18-byte asm. The shift/XOR
portion already lowers well; the remaining waste is a redundant reload after
storing the newly computed RNG byte before immediately testing it for zero. The
compiler still has the value in A with valid Z/N flags at that point, but loses
that value/condition-code fact across the statement boundary. Do not add a
Tanks/LFSR-specific peephole. Find the smallest general value/flags-lifetime or
store-then-condition optimization, regression-test it, then remeasure and only
then replace `tanks_random()` in the example. `tanks_process_knockback()` remains
handwritten asm and should be attacked afterward with the same small-step
measure/explain/fix/retest method.
