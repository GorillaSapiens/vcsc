2026-09-04 09:07:18 PDT, implement and certify F0 automatic bankcalls
Added the F0 mapper as exactly 16 physical 4K banks / 64K with hardware startup
in physical bank 15.  F0 descriptors are physical bank IDs 0..15.  The replicated
96-byte transition advances $1FF0 by the forward modulo-16 distance to the
callee and by the inverse distance on return, so nested calls restore source
banks without a runtime mapper-state byte.  The linker keeps ordinary code below
$FFF0 because fetching that address itself advances F0.  Compiler, linker,
simulator, disassembler, generated bankcall source, staged install data, public
documentation, and the independent frame-timing oracle all understand F0.

15, round-trips byte-for-byte through vcsc-disas, and holds 262-line NTSC frames.
The assembler now suppresses transient segment-overflow warnings during
relaxation and diagnoses overflow only from a stable final layout, allowing an
exactly-full 64K F0 roundtrip without false stderr while preserving real overflow
warnings.  Disassembler hardening now treats 64K as a valid F0 container size,
uses 65535/65537 as malformed neighbors, and still rejects a structurally valid

2026-09-04 09:35:36 PDT, constrain E0 compiler states
E0 automatic calls will not preserve arbitrary 9-bit mapper state.  VCSC C26
supports only [0,1,6,7], [2,3,6,7], and [4,5,6,7].  Banks 0/2/4 have canonical
origin $1000, banks 1/3/5 origin $1400, bank 6 stays at $1800, and bank 7 is
fixed at $1C00.  Cross-state calls switch the lower pair together and restore
the previous pair on return; calls within a pair or to banks 6/7 need no mapper
transition.  Hardware startup [4,5,6,7] already supplies the desired bank-6
mapping.  Arbitrary E0 window combinations remain available only to deliberate
assembly outside the automatic-call ABI, analogous to WD's constrained states.

2026-09-04 10:59:28 PDT, implement constrained-state E0 bankcalls
Implemented E0 automatic bankcalls using only canonical states [0,1,6,7],
[2,3,6,7], and [4,5,6,7]. Banks 0/2/4 retain canonical origin $1000,
banks 1/3/5 $1400, resident bank 6 $1800, and fixed bank 7 $1C00. Descriptors
0/1/2 select the three lower pairs; resident banks 6/7 use $FF. One RIOT-RAM
byte `_vcsc_e0_state` tracks only the canonical state so nested calls made from
resident banks can switch another pair and still restore their caller. Hardware
reset already supplies state 2, so E0 entry code is empty. Arbitrary E0 selector
arrangements remain outside the automatic-call ABI.

The E0 trampoline reserves 112 bytes per physical 1K bank and its generated
source uses dynamic state save/restore rather than a baked source descriptor.
The linker now permits direct ROM references only between banks guaranteed
simultaneous in one canonical E0 state and rejects cross-state ROM data
references. vcsc-sim, the independent frame-timing oracle, vcsc-disas, profile
inspection, generated-template/install contracts, and the public E0 diagnostic
all understand the constrained model. The diagnostic executes all 8 x 8 ordered
physical-bank calls, resident-bank nested restoration, a 16-bit A:X return,
262-line NTSC timing, E0 autodetection, and exact disassembly roundtrip.

Generic profile/example tests were updated for the new E0 topology: the profile
fixture supplies its own E0 mapper/main, the assembly allowlist reflects the new
37-statement display block, and example vector validation accepts E0's fixed
$1C00-$1FFF vector window. Validation completed with 503/503 compile-only tests
and 356/356 e2e tests with eight workers; staged `make installcheck` also passes.
The planned automatic-call mapper migration is complete. FE remains intentionally
special, and the separate Stella 3EX >64K RAM-write defect remains tracked in
.../3ex.txt.

2026-09-04 12:11:08 PDT, remove general cross-bank JMP support
Removed the legacy generic mapper-changing direct-JMP trampoline from the
linker. Ordinary direct JMP relocations are now a hard same-bank constraint;
explicit pinned cross-bank JMP targets fail with a dedicated diagnostic and
automatically placed JMP source/target code is co-located. The old replicated
8-byte JMP-entry encoder/allocation path is gone. Mapper-changing one-way JMP
is now reserved solely for reset/startup: each bank's replicated vector bridge
runs that mapper's maintained `entry.s26` normalization bytes when necessary,
then performs the ordinary absolute JMP to the reset handler. Per-bank reset
bridge and mapper-entry regeneration tests certify that startup behavior.

Reworked the F8/F6/F4(+SC) diagnostic to use only the normal bankcall ABI for
its complete ordered call matrix. The diagnostic-only inline cross-bank JMP
phase, jump_target0..7 helpers, and their BNE/JMP/JMP optimizer wart are gone.
Linker relocation tests now require cross-bank JMP rejection and retain a
same-bank JMP acceptance case. Documentation and hygiene contracts state that
application JMP is bank-local while cross-bank C26 control flow is call/return.
Validation passes 503/503 compile-only and 356/356 e2e tests with eight workers;
`make installcheck` also passes.
