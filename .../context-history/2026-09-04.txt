2026-09-04 07:38:41 PDT, implement FC automatic bankcalls
Added one parameterized FC mapper for 1..256 physical 4K banks, covering 4K
through 1 MiB cartridges.  FC descriptors are physical/file bank numbers;
bankcalls stage descriptor bits through $1FF8 and $1FF9 and commit through
$1FFC.  Bank 0 is the hardware startup bank, so FC needs no entry code.  The
compiler, linker, simulator, disassembler, generated bankcall source, install
rules, public mapper documentation, and independent frame-timing oracle now
understand FC.

Added public example 09_bankswitching/21_fc.  Its maintained diagnostic executes
the complete ordered 8 x 8 bankcall matrix, nested restoration, and a 16-bit
A:X return check while preserving 262-line NTSC frames.  test/vcs_fc.pl also
builds a 256-bank 1 MiB edge cartridge and executes descriptor $FF, including a
nested bank255 -> bank127 -> bank255 -> bank0 return path.  The disassembler
autodetects the generated FC cartridge and reports the staged selector protocol.

2026-09-04 09:07:18 PDT, implement and certify F0 automatic bankcalls
Added the F0 mapper as exactly 16 physical 4K banks / 64K with hardware startup
in physical bank 15.  F0 descriptors are physical bank IDs 0..15.  The replicated
96-byte transition advances $1FF0 by the forward modulo-16 distance to the
callee and by the inverse distance on return, so nested calls restore source
banks without a runtime mapper-state byte.  The linker keeps ordinary code below
$FFF0 because fetching that address itself advances F0.  Compiler, linker,
simulator, disassembler, generated bankcall source, staged install data, public
documentation, and the independent frame-timing oracle all understand F0.

Added public example 09_bankswitching/22_f0 and test/vcs_f0.pl.  The maintained
diagnostic executes all 16 x 16 = 256 ordered source/destination calls, checks
nested restoration and a 16-bit A:X return, starts naturally in hardware bank
15, round-trips byte-for-byte through vcsc-disas, and holds 262-line NTSC frames.
The assembler now suppresses transient segment-overflow warnings during
relaxation and diagnoses overflow only from a stable final layout, allowing an
exactly-full 64K F0 roundtrip without false stderr while preserving real overflow
warnings.  Disassembler hardening now treats 64K as a valid F0 container size,
uses 65535/65537 as malformed neighbors, and still rejects a structurally valid
64K image containing no instructions.

Validation completed with 503/503 compile-only tests and 356/356 e2e tests with
eight workers.  The staged make installcheck passes.  Loaded-run timeout budgets
were raised only for the exhaustive asymmetric-multisprite oracle and example
build shard 1; their behavioral coverage is unchanged.  F0 roadmap work is
complete; E0 automatic-call design is next.

2026-09-04 09:35:36 PDT, constrain E0 compiler states
E0 automatic calls will not preserve arbitrary 9-bit mapper state.  VCSC C26
supports only [0,1,6,7], [2,3,6,7], and [4,5,6,7].  Banks 0/2/4 have canonical
origin $1000, banks 1/3/5 origin $1400, bank 6 stays at $1800, and bank 7 is
fixed at $1C00.  Cross-state calls switch the lower pair together and restore
the previous pair on return; calls within a pair or to banks 6/7 need no mapper
transition.  Hardware startup [4,5,6,7] already supplies the desired bank-6
mapping.  Arbitrary E0 window combinations remain available only to deliberate
assembly outside the automatic-call ABI, analogous to WD's constrained states.
