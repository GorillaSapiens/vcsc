VCSC DISASSEMBLER: DURABLE CONTRACT AND OPEN WORK
=================================================

Purpose
-------
`vcsc-disas` turns an Atari 2600 cartridge image into VCSC `.s26` that
`vcsc-as` can reassemble **byte-for-byte exactly**. Readability and inference are
important, but exact reconstruction wins every conflict. Completed development
history is in `.../context-history/`; the pre-cleanup full roadmap is archived in
2026-08-22.

Durable invariants
------------------
* Never normalize the image. Preserve file length, duplicate banks, inaccessible
  bytes, fill, vector oddities, and trailing preservation bytes exactly.
* Identical input plus identical command line must produce identical `.s26`.
* If semantic interpretation is uncertain, emit exact raw bytes and annotate the
  uncertainty. A zero-instruction result is still a hard analysis failure.
* Physical file position and 6507 runtime address are distinct. Use `.org` for
  physical output and `.rorg`/`.rend` for runtime PC. Preserve encoded mirrored
  addresses when changing them would alter operand bytes.
* A real `JMP ($xxFF)` must remain raw bytes because `vcsc-as` deliberately
  rejects that hazardous NMOS spelling.
* Conditional branches must carry deterministic `.same`/`.cross` timing when
  emitted symbolically; if the one-bank presentation cannot represent the real
  mapper-resolved relative target, keep the original bytes raw.
* Established execution evidence controls mapper/video/controller/hardware
  decisions. Detached speculative islands may improve presentation but must not
  promote mapper hypotheses, Superchip semantics, or execution roots.
* Generated headers preserve mapper-inference provenance.  When multiple
  size-compatible mapper models are tested, report the selected/retained
  decision mode plus every tested hypothesis as viable or rejected with the
  actual reason.  Positive selector/signature evidence and negative
  HLT/JAM/KIL/contradiction evidence must remain distinguishable; if the legacy
  size/default mapper survives an unresolved ambiguity, say so rather than
  presenting it as positive proof.
* Mapper inference is a hardware-state problem, not merely a file-size/name
  lookup. Keep mapper context separate when following code across selectors.
* Detached speculative validation uses a local sparse fixed point keyed by
  physical instruction byte, runtime PC, and mapper context. Arrivals in the
  same context meet successor-relevant abstract CPU/ZP facts and requeue only
  when knowledge decreases. Viability is edge/path based: one dead arm of a
  conditional branch is allowed when another feasible arm remains live; all
  feasible dead arms reject backward, while JSR requires both callee and return
  continuation. JAM/KIL/HLT and impossible execution/hardware accesses are dead
  speculative edges. A speculative memory write must also have a real sink in
  the established hardware model (RAM/write port, valid device register, or a
  direction-valid mapper/peripheral side effect); plain ROM/unclaimed writes are
  dead, with the structural prefilter conservative about unresolved mapper-RAM
  state. Official/stable-unofficial/unstable-unofficial opcodes and
  canonical/mirrored TIA/RIOT accesses provide graded promotion evidence; known
  direction-sensitive mapper hotspots override the generic hardware score. There
  is no traversal/node cap; allocation failure is inconclusive and may never
  strengthen promotion or rejection.
* RESET is the only stock-6507 initial hardware execution root. Reachable `BRK`
  may promote IRQ/BRK; NMI is never rooted merely from `$FFFA/$FFFB`. For a
  signed VCSC banked image, the complete linker vector-bridge invariant may
  establish the three bridge slots as code without making NMI/IRQ handlers
  runtime-reachable. Signature bytes alone are insufficient.
* Multi-game containers are separate cartridge analyses concatenated in original
  order; no CFG or ROM reference crosses a component boundary.
* The standalone `disassembler/roundtrip.pl` remains the mechanical exactness
  oracle. Stella differential mapper checks are useful evidence, not authority.
* A successful CLI run reports its destination on standard error only after the
  requested output has been written and closed successfully (and multicart
  sidecars, when applicable, also succeeded). `-o -` reports `stdout`. Every
  nonzero exit ends stderr with `Failure, disassembly not written` after the
  specific diagnostic. Bulk `roundtrip.pl` validation consumes and checks the
  per-file success confirmation.

Analysis architecture roadmap -- mapper-hypothesis execution
----------------------------------------------------------
This is the highest-priority disassembler analysis subitem.  The destination is
state-space exploration of every structurally possible mapper hypothesis, rather
than "guess mapper -> decide whether it is trusted -> maybe simulate".  Mapper
identity and reachable-code/data discovery must emerge together from isolated
hardware models.  Work through these pieces in order; keep each step regression-
locked before replacing the next existing heuristic.

A1. [ ] Duplicate-image analysis view and provenance map
    * Repeatedly halve the analysis image while its two halves are byte-identical,
      until the smallest unique payload remains.  This is analysis-only: never
      change physical output size or bytes, and retain a many-to-one provenance
      map from every unique byte/bank back to every physical copy.
    * Record exact duplicates and wholly erased/fill banks as explained physical
      content so later bank-coverage checks do not mistake dump padding for an
      inaccessible game bank.

A2. [ ] Enumerate mapper hypotheses before choosing a winner
    * From physical size, unique size, explicit metadata/signatures, and mapper
      structural constraints, construct every mapper model that could physically
      explain the image.  Do not select a trusted/default mapper first.
    * Keep hypotheses isolated: mapper/RAM state, runtime mapping, discovered
      code/data, rejection reasons, and evidence may never leak between them.

A3. [ ] Turn concrete discovery into exhaustive state-space exploration
    * Start each hypothesis from every hardware-legal RESET startup state required
      by that mapper.  When register/flag state proves a branch direction, follow
      only that edge.  When it does not, fork and follow every feasible edge.
      Unknown inputs are symbolic uncertainty, not hand-picked "game modes" or
      scenario samples.
    * Deduplicate equivalent machine states and widen finite abstract values as
      needed; loop convergence must not depend on an instruction-count cap.
    * Remove the current mapper-trust gate once hypothesis-local execution is safe;
      `--mapper` must constrain the hypothesis set, not secretly enable a stronger
      analysis engine.

A4. [ ] First-class value/source provenance
    * Track ROM-byte provenance through registers, arithmetic where practical,
      RIOT/cartridge RAM stores and reloads, and instruction fetch from executable
      RAM.  Generated RAM code must therefore retain the ROM bytes that created
      each opcode/operand.  Congo Bongo's ROM constants -> $00F0..$00F5 ->
      `LDA $FFF8 ; JMP $F0E0` is the canonical regression.
    * Track provenance into externally meaningful sinks, initially GRP0/GRP1 and
      later the other display/audio consumers where useful.  This lets bytes read
      as tables/graphics be explained as data instead of competing with speculative
      instruction decoding.
    * Preserve provenance across bank switches/mirrors while retaining physical
      byte identity for exact reconstruction.

A5. [ ] Unified path viability and hardware-bus rejection
    * Reuse the detached-island rules as execution semantics: JAM/KIL/HLT kills
      that path; branch/JMP/JSR to neither cartridge nor executable RAM kills the
      affected edge/path; impossible/no-source reads and no-sink writes/RMW kill
      the affected path after direction-sensitive mapper/peripheral exceptions.
    * A conditional survives when at least one feasible successor survives.  If
      known state makes one arm impossible, do not explore it.  If every feasible
      arm dies, rejection propagates backward.  JSR requires a viable callee and
      a viable return continuation.
    * Canonical TIA/RIOT accesses are stronger code evidence than legal mirrors.
      Mapper-defined nonstandard addresses are judged by that mapper first and may
      override the generic TIA/RIOT interpretation in the appropriate direction.

A6. [ ] Bank-access completeness as a mapper requirement
    * Exhaustive execution must account for every unique, non-fill bank under a
      surviving mapper: at least one feasible path must fetch instructions from it
      or read data from it.  Exact duplicate and erased/fill banks are already
      accounted for by A1 and do not require synthetic execution.
    * A mapper hypothesis that leaves a unique meaningful bank wholly inaccessible
      is rejected, not excused as an untriggered game mode.  Unknown input/control
      state should have forked before this check.
    * Report per-bank evidence: instruction fetch, data read, RAM-code provenance,
      display/audio provenance, duplicate, fill, or unexplained.

A7. [ ] Compare surviving hypotheses from contradictions plus positive evidence
    * Mapper-specific hotspot activity, coherent continuation after a bank change,
      correct cartridge-RAM behavior, generated-RAM selectors, reset behavior, and
      complete bank access are positive evidence.  Merely executing many
      instructions is not mapper evidence.
    * Reject hypotheses on hard contradictions.  If exactly one survives, select
      it.  If several survive without a principled discriminator, report the
      ambiguity and preserve conservative/raw presentation rather than allowing a
      size default or self-confirming model to masquerade as proof.
    * Keep signatures/static heuristics as migration priors and diagnostics, not
      prerequisites for running a hypothesis.  Retire trust/default machinery only
      after equivalent negative regressions exist.

A8. [ ] Feed exhaustive execution back into code/data presentation
    * Established execution under the selected hypothesis remains authoritative.
      ROM bytes proven to feed executable RAM are code-source data; bytes proven to
      feed GRP0/GRP1 or other consumers are data-source evidence.  Preserve exact
      bytes even when one physical byte has more than one runtime role.
    * Revisit detached island discovery after hypothesis execution is mature: it
      should fill genuinely unreachable presentation gaps, not compensate for an
      execution engine that failed to explore feasible control flow.
    * Regression set must include Congo Bongo's generated F8 selector, the prior
      false-mapper cases that motivated the trust gate, duplicate/padded images,
      all-bank coverage, unknown-input branch forking, and mapper-specific
      read/write hotspot direction.

Weak "nonsense operation string" evidence
-----------------------------------------
Maintain a deliberately weak plausibility signal for short instruction sequences
whose semantic work is immediately obliterated.  This may indicate speculative
decoding drifted into data, but is never a hard rejection: beam-path code may burn
cycles with semantically redundant operations.

Prefer a small dead-definition/dataflow analysis over a catalog of byte strings.
For each instruction, describe CPU definitions/uses (A/X/Y/SP, individual flags,
memory) plus externally visible bus effects.  A definition is suspicious when
all of its semantic effects are overwritten before any use and the instruction
had no meaningful read/write/mapper/device side effect.  Examples include:

* `LDA #$00 ; LDA #$FF` when neither A nor the first N/Z result is observed.
* `LDX #a ; LDX #b`, `LDY #a ; LDY #b`, or repeated register transfers where the
  first result is dead before use.
* `CLC ; SEC`, `SED ; CLD`, or similar flag definitions when the first flag value
  is neither branched/tested nor consumed by ADC/SBC/rotate before replacement.
* A pure load from ordinary RAM followed by another full load of that register
  before the value or resulting flags are used.
* Arithmetic/INC/DEC/transfer work whose register and flag results are completely
  overwritten before any observable use.
* A RAM store whose value is overwritten at the same location before any feasible
  read, when neither store has device/mapper semantics.
* `JMP`/branch to the immediately following instruction, or other control-flow
  detours that have no semantic effect except cycles.

Do **not** call a sequence nonsense merely because it looks redundant locally:

* TIA/RIOT, cartridge peripheral, and mapper reads/writes may have bus side effects.
* Stores to TIA registers are often timing/output actions even when the same value
  is written repeatedly.
* Reads used for bankswitching may matter even when the loaded value is discarded.
* PHA/PLA, PHP/PLP, transfers, flag changes, unofficial opcodes, and apparently
  redundant ALU operations may exist solely to consume a precise number of cycles.
* Once execution is known to be in or near the visible beam path (for example,
  bounded by WSYNC/display activity), suppress or sharply reduce this penalty.
  Timing-only code during blanking is also possible, so beam-path knowledge changes
  the weight rather than proving semantic purpose.

Accumulate this evidence gently.  One dead definition should barely matter;
several independent dead/clobbered definitions in a short speculative run can
lower island/hypothesis confidence.  Cap the penalty so nonsense scoring can
never by itself kill a path or mapper.  Hard hardware/control-flow contradictions
remain separate.  If execution/provenance later proves the sequence reachable,
keep it as code and use the signal only as a diagnostic annotation/statistic.

Current direction
-----------------
The mapper-hypothesis execution roadmap A1-A8 above is now the current analysis
priority.  It replaces the trusted-winner-first architecture with exhaustive,
hypothesis-local state-space exploration and provenance; implement it incrementally
without weakening exact reconstruction or the existing negative mapper regressions.
GL implementation remains complete with only real-corpus closeout pending; CM, DPC+,
and the CDF family remain the mapper-specific queue after/alongside that migration.

When corpus work resumes, prefer one concrete mismatch/failure category at a
time, add a minimal synthetic regression plus the real corpus case, and keep
exact round trip non-negotiable. Do not grow this file with per-ROM victory
narratives; put those in the daily history.
