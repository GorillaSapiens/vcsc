VCSC DISASSEMBLER: DURABLE CONTRACT AND OPEN WORK
=================================================

Purpose
-------
`vcsc-disas` turns an Atari 2600 cartridge image into VCSC `.s26` that
`vcsc-as` can reassemble **byte-for-byte exactly**. Readability and inference are
important, but exact reconstruction wins every conflict. Completed development
history is in `.../context-history/`; the pre-cleanup full roadmap is archived in
2026-08-22.

Durable invariants
------------------
* Never normalize the physical image. Preserve file length, duplicate banks,
  inaccessible bytes, fill, vector oddities, and trailing preservation bytes
  exactly. Automatic analysis has an A1 duplicate view: recursively halve exact
  repeated halves to the smallest unique prefix, retain byte provenance to every
  physical copy, and record exact-duplicate plus `$00`/`$FF` fill banks as
  explained content. Explicit mapper/layout overrides retain physical bank
  topology while keeping that provenance.
* Identical input plus identical command line must produce identical `.s26`.
* If semantic interpretation is uncertain, emit exact raw bytes and annotate the
  uncertainty. A zero-instruction result is still a hard analysis failure.
* Physical file position and 6507 runtime address are distinct. Use `.org` for
  physical output and `.rorg`/`.rend` for runtime PC. Preserve encoded mirrored
  addresses when changing them would alter operand bytes.
* A real `JMP ($xxFF)` must remain raw bytes because `vcsc-as` deliberately
  rejects that hazardous NMOS spelling.
* Conditional branches must carry deterministic `.same`/`.cross` timing when
  emitted symbolically; if the one-bank presentation cannot represent the real
  mapper-resolved relative target, keep the original bytes raw.
* Established execution evidence controls mapper/video/controller/hardware
  decisions. Detached speculative islands may improve presentation but must not
  promote mapper hypotheses, Superchip semantics, or execution roots.
* Generated disassembly and diagnostics are self-describing. Never expose
  internal roadmap-stage labels such as `A5`, `A7`, or `H2` in user-visible
  output; describe the actual analysis instead. Hardware names such as the 0840
  mapper's address line A6 are not roadmap labels.
* Generated headers preserve mapper-inference provenance.  When multiple
  structurally compatible mapper models are tested, report the A7 comparison
  result plus every tested hypothesis as surviving, outcompeted, or contradicted
  with the actual reason. Positive selector/signature evidence and negative
  HLT/JAM/KIL/bus contradictions remain distinguishable. Unresolved hypotheses
  never inherit the old size/default winner: use conservative/raw presentation
  unless the surviving models are observationally equivalent for presentation.
* Mapper inference is a hardware-state problem, not merely a file-size/name
  lookup. Keep mapper context separate when following code across selectors.
* Detached speculative validation uses a local sparse fixed point keyed by
  physical instruction byte, runtime PC, and mapper context. Arrivals in the
  same context meet successor-relevant abstract CPU/ZP facts and requeue only
  when knowledge decreases. Viability is edge/path based: one dead arm of a
  conditional branch is allowed when another feasible arm remains live; all
  feasible dead arms reject backward, while JSR requires both callee and return
  continuation. JAM/KIL/HLT and impossible execution/hardware accesses are dead
  speculative edges. A speculative memory write must also have a real sink in
  the established hardware model (RAM/write port, valid device register, or a
  direction-valid mapper/peripheral side effect); plain ROM/unclaimed writes are
  dead, with the structural prefilter conservative about unresolved mapper-RAM
  state. Official/stable-unofficial/unstable-unofficial opcodes and
  canonical/mirrored TIA/RIOT accesses provide graded promotion evidence; known
  direction-sensitive mapper hotspots override the generic hardware score. There
  is no traversal/node cap; allocation failure is inconclusive and may never
  strengthen promotion or rejection.
* RESET is the only stock-6507 initial hardware execution root. Reachable `BRK`
  may promote IRQ/BRK; NMI is never rooted merely from `$FFFA/$FFFB`. For a
  deliberate `RESET=$0000`, the reset-vector high-byte fetch leaves `$00` on
  the data bus and the following opcode fetch from write-only TIA `$0000`
  returns open-bus `$00` (`BRK`); this deterministic hardware bootstrap makes
  the IRQ/BRK vector a reachable startup continuation. Other non-ROM RESET
  targets remain invalid unless separately proven. For a
  signed VCSC banked image, the complete linker vector-bridge invariant may
  establish the three bridge slots as code without making NMI/IRQ handlers
  runtime-reachable. Signature bytes alone are insufficient.
* Mapper hypotheses are enumerated before any legacy/default winner is chosen.
  Automatic cart hypotheses come from structural compatibility with the A1 unique
  analysis size; detector/tail signatures annotate those hypotheses but do not
  create an incompatible topology.  Structurally compatible models that the old
  static flow refiner never compared remain in the set for A3 instead of being
  silently discarded.  Hypothesis-local analysis/evidence may never leak between
  candidates.
* `2IN1`, `4IN1`, `8IN1`, `32IN1`, and future N-in-1 schemes are a parameterized
  first-class mapper-hypothesis family, not a post-mapper container category.
  Automatic N-in-1 structure is derived from the physical image while ordinary
  cart structure uses the A1 unique view; exact duplicate constituents therefore
  remain preservation evidence rather than inventing a multicart.  The selector
  state chooses which constituent image is CPU-visible and no CFG/ROM reference
  crosses an unselected constituent.  Current `.gameNN.s26` sidecars and the
  `--container` spelling are compatibility presentation/override plumbing only.
* The standalone `disassembler/roundtrip.pl` remains the mechanical exactness
  oracle. Stella differential mapper checks are useful evidence, not authority.
* A successful CLI run reports its destination on standard error only after the
  requested output has been written and closed successfully (and multicart
  sidecars, when applicable, also succeeded). `-o -` reports `stdout`. Every
  nonzero exit ends stderr with `Failure, disassembly not written` after the
  specific diagnostic. Bulk `roundtrip.pl` validation consumes and checks the
  per-file success confirmation.

Completed mapper-hypothesis architecture
----------------------------------------
A1 duplicate-image provenance, A2 preselection enumeration, A3 hypothesis-local
state-space execution, A4 first-class provenance, A5 unified viability, A6
bank-access completeness, A7 final evidence comparison, and A8 presentation
feedback are complete.

Completed mapper-analysis invariants
------------------------------------
A3-A8 execute every structurally compatible hypothesis independently from all
legal RESET states, preserve ROM/RAM/generated-code/display provenance, reject
only hard-dead feasible paths, compare survivors by corroborated hardware
evidence rather than instruction count/default size, and replay only the chosen
A5-viable hypothesis into trusted presentation. Model-created RAM/selector
behavior cannot prove its own mapper family; unresolved ties stay exact/raw.
Detached islands remain presentation-only and never vote on mapper identity.
Exact duplicate/fill provenance, N-in-1 topology, Superchip overlays, broad
partial decoders, explicit VCSC metadata, and post-A8 overlap-evidence rules are
covered by focused regressions and dated history.

Completed graphics/provenance sequence
--------------------------------------
G1-G5 recover graphics because established execution proves dataflow to TIA
display sinks, never because arbitrary ROM bytes merely look pictorial. The
analysis stays mapper-context-aware, exact-round-trip neutral, and presentation-
only; graphics evidence never votes on mapper identity.

Completed G1 invariant
----------------------
Finite multi-origin display provenance is complete. Selected-hypothesis execution
carries capped may-source sets through A/X/Y, deterministic ALU/transfers, RIOT
RAM, cartridge RAM, and stack staging to GRP0/GRP1/PF0/PF1/PF2. Display
provenance is deliberately separate from the exact single-source A4 channel, so
it can add presentation/data/graphics roles but can never become mapper evidence.
RIOT/cart staging uses sparse state maps to keep exhaustive execution within the
normal regression time budget; overflow loses optional sources conservatively and
never invents one. Alternative-branch RIOT and cartridge-RAM merges are locked by
synthetic regressions and exact round trips.

Completed G2 invariant
----------------------
Indirect graphics-pointer recovery is complete. Established `(zp),Y` consumers
that feed display registers may use finite mapper-local pointer domains recovered
from split low/high assignments, inherited singleton bytes, bounded binary
ADC/SBC updates, and the common `LDX #n ; LDA table,X ; STA zp,X ; DEX ; BPL`
startup block copy. Domains are capped and deterministic; uncertain arithmetic,
decimal-mode arithmetic, overflowed domains, and independently varying low+high
sets stay unknown rather than manufacturing targets. A short RIOT staging hop is
recognized when deciding whether an unresolved indirect load feeds graphics.
Synthetic regressions lock block-copy+ADC/SBC recovery and branch-merged split
pointer targets. Graphics recovery remains presentation-only and cannot vote on
mapper identity.

Completed G3 invariant
----------------------
Loop-derived graphics spans are complete. Established indexed/indirect consumers
recover exact source-row intervals from countdown loops, increment-to-limit loops,
and copy loops whose controlling register differs from the source index. Proven
GRP0/GRP1 spans retain exact 8xN sprite-height metadata; PF0/PF1/PF2 spans remain
playfield graphics without sprite classification. Proven spans may overlap code
and preserve both roles; only unproven cases retain the bounded fallback window.
Synthetic regressions lock separated index setup, 8x16 countdown graphics,
compare-limited spans, RIOT-buffer copy lengths, and exact reconstruction.

Completed G4 invariant
----------------------
Finite selector/offset-table sprite families are complete. A runtime X/Y selector
may expand an indexed ROM table only when nearby straight-line dataflow proves a
small finite selector domain (currently exact state, immediate selection, or an
unknown value constrained by a low contiguous AND mask with optional disjoint OR
bits). Every selected table value may flow through the existing bounded pointer
arithmetic, then G3's loop-derived span is applied to each recovered target.
Established instruction/vector bytes are not invented as selector-table members;
real code/data overlap still requires execution/provenance evidence. Synthetic
regressions lock a four-member 8x16 family and bitmap-looking/code-adjacent false
positives outside the proven selector domain.

Completed G5 invariant
----------------------
Presentation emits `probable 8xN sprite` for proven GRP0/GRP1 spans; never use
`player sprite`. Visual binary rows, fonts, pointer/table formatting, executable
overlap, and other simultaneous byte roles remain exact-round-trip compatible.
When instruction bytes are also proven data, the overlap comment identifies the
specific opcode/operand byte roles rather than using a generic instruction-wide
message.
When a proven sprite span and a proven COLUP0/COLUP1 table are consumed by the
same indexed loop with the same X/Y register, back-edge, row interval, and
corresponding GRP0/COLUP0 or GRP1/COLUP1 sinks, presentation links them as a
parallel per-row sprite/color pair. Equal lengths, adjacency, mismatched players,
or separate loops are insufficient; ambiguous relationships stay independent.
Synthetic tests own sprite-height, exclusion, overlap, family, and joined-pointer
cases; copyrighted real-ROM validation stays out of tree.

Weak "nonsense operation string" evidence
-----------------------------------------
Use only as a weak detached-code plausibility signal: a definition is suspicious
when its register/flag/RAM result is overwritten before any feasible use and the
operation had no meaningful bus/device/mapper side effect. Hardware accesses,
bankswitch reads, stack/unofficial operations, and beam/blanking timing may be
intentional cycle work, so they sharply suppress the penalty. Accumulate gently,
cap the penalty, never let it kill a path/mapper by itself, and never demote
proven reachable code.

Current direction
-----------------
A1-A8, both post-A8 mapper-hardening passes, and G1-G5 are complete. GL real-
corpus closeout is next, followed by CM, DPC+, and CDF-family support. Mapper ties
still stay raw; keep real-ROM narratives in dated history and repository tests
synthetic/non-copyrighted.

Post-A8 corpus hardening
-------------------------
Keep unsupported CDF-family fingerprints exact/raw rather than mislabeling them
as F4/F0. A weak sole A5 survivor does not become confident merely because a
detector-signed alternative was hard-rejected; the contradiction still stands,
but the conflicting static signal blocks an evidence-free fallback. Stella
differential comparisons normalize exact duplicate F8/F6/F4/F0 wrappers to the
same smallest-unique-image policy used by VCSC.

For overlap evidence, require corroboration before model-created behavior can
vote. CV/WD/E7/GL RAM traffic and broad 0840/UA/UASW/0FA0 decoder coverage are
diagnostic until detector/explicit metadata, switch-save, or proven generated
selector evidence establishes the family. FC/3E multi-access protocol
fingerprints are independent evidence when that hypothesis remains A5-live. On
8K E0/E7 images, shared $1FE4-$1FEB selectors are not family-specific. FE JSR
target-high activity is specific only with independent FE evidence; `FE\0\0`
is explicit metadata. Structural Superchip layout/tail evidence activates the
SC overlay during A5, and writes through the SC read alias are harmless bus
writes rather than SC-RAM writes or hard contradictions.
