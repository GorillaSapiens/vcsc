VCSC DISASSEMBLER: DURABLE CONTRACT AND OPEN WORK
=================================================

Purpose
-------
`vcsc-disas` turns an Atari 2600 cartridge image into VCSC `.s26` that
`vcsc-as` can reassemble **byte-for-byte exactly**. Readability and inference are
important, but exact reconstruction wins every conflict. Completed development
history is in `.../context-history/`; the pre-cleanup full roadmap is archived in
2026-08-22.

Durable invariants
------------------
* Never normalize the physical image. Preserve file length, duplicate banks,
  inaccessible bytes, fill, vector oddities, and trailing preservation bytes
  exactly. Automatic analysis has an A1 duplicate view: recursively halve exact
  repeated halves to the smallest unique prefix, retain byte provenance to every
  physical copy, and record exact-duplicate plus `$00`/`$FF` fill banks as
  explained content. Explicit mapper/layout overrides retain physical bank
  topology while keeping that provenance.
* Identical input plus identical command line must produce identical `.s26`.
* If semantic interpretation is uncertain, emit exact raw bytes and annotate the
  uncertainty. A zero-instruction result is still a hard analysis failure.
* Physical file position and 6507 runtime address are distinct. Use `.org` for
  physical output and `.rorg`/`.rend` for runtime PC. Preserve encoded mirrored
  addresses when changing them would alter operand bytes.
* A real `JMP ($xxFF)` must remain raw bytes because `vcsc-as` deliberately
  rejects that hazardous NMOS spelling.
* Conditional branches must carry deterministic `.same`/`.cross` timing when
  emitted symbolically; if the one-bank presentation cannot represent the real
  mapper-resolved relative target, keep the original bytes raw.
* Established execution evidence controls mapper/video/controller/hardware
  decisions. Detached speculative islands may improve presentation but must not
  promote mapper hypotheses, Superchip semantics, or execution roots.
* Generated headers preserve mapper-inference provenance.  When multiple
  structurally compatible mapper models are tested, report the A7 comparison
  result plus every tested hypothesis as surviving, outcompeted, or contradicted
  with the actual reason. Positive selector/signature evidence and negative
  HLT/JAM/KIL/bus contradictions remain distinguishable. Unresolved hypotheses
  never inherit the old size/default winner: use conservative/raw presentation
  unless the surviving models are observationally equivalent for presentation.
* Mapper inference is a hardware-state problem, not merely a file-size/name
  lookup. Keep mapper context separate when following code across selectors.
* Detached speculative validation uses a local sparse fixed point keyed by
  physical instruction byte, runtime PC, and mapper context. Arrivals in the
  same context meet successor-relevant abstract CPU/ZP facts and requeue only
  when knowledge decreases. Viability is edge/path based: one dead arm of a
  conditional branch is allowed when another feasible arm remains live; all
  feasible dead arms reject backward, while JSR requires both callee and return
  continuation. JAM/KIL/HLT and impossible execution/hardware accesses are dead
  speculative edges. A speculative memory write must also have a real sink in
  the established hardware model (RAM/write port, valid device register, or a
  direction-valid mapper/peripheral side effect); plain ROM/unclaimed writes are
  dead, with the structural prefilter conservative about unresolved mapper-RAM
  state. Official/stable-unofficial/unstable-unofficial opcodes and
  canonical/mirrored TIA/RIOT accesses provide graded promotion evidence; known
  direction-sensitive mapper hotspots override the generic hardware score. There
  is no traversal/node cap; allocation failure is inconclusive and may never
  strengthen promotion or rejection.
* RESET is the only stock-6507 initial hardware execution root. Reachable `BRK`
  may promote IRQ/BRK; NMI is never rooted merely from `$FFFA/$FFFB`. For a
  signed VCSC banked image, the complete linker vector-bridge invariant may
  establish the three bridge slots as code without making NMI/IRQ handlers
  runtime-reachable. Signature bytes alone are insufficient.
* Mapper hypotheses are enumerated before any legacy/default winner is chosen.
  Automatic cart hypotheses come from structural compatibility with the A1 unique
  analysis size; detector/tail signatures annotate those hypotheses but do not
  create an incompatible topology.  Structurally compatible models that the old
  static flow refiner never compared remain in the set for A3 instead of being
  silently discarded.  Hypothesis-local analysis/evidence may never leak between
  candidates.
* `2IN1`, `4IN1`, `8IN1`, `32IN1`, and future N-in-1 schemes are a parameterized
  first-class mapper-hypothesis family, not a post-mapper container category.
  Automatic N-in-1 structure is derived from the physical image while ordinary
  cart structure uses the A1 unique view; exact duplicate constituents therefore
  remain preservation evidence rather than inventing a multicart.  The selector
  state chooses which constituent image is CPU-visible and no CFG/ROM reference
  crosses an unselected constituent.  Current `.gameNN.s26` sidecars and the
  `--container` spelling are compatibility presentation/override plumbing only.
* The standalone `disassembler/roundtrip.pl` remains the mechanical exactness
  oracle. Stella differential mapper checks are useful evidence, not authority.
* A successful CLI run reports its destination on standard error only after the
  requested output has been written and closed successfully (and multicart
  sidecars, when applicable, also succeeded). `-o -` reports `stdout`. Every
  nonzero exit ends stderr with `Failure, disassembly not written` after the
  specific diagnostic. Bulk `roundtrip.pl` validation consumes and checks the
  per-file success confirmation.

Analysis architecture roadmap -- mapper-hypothesis execution
----------------------------------------------------------
Highest-priority analysis subitem: explore every structurally possible mapper
hypothesis instead of "guess -> trust -> maybe simulate". Mapper identity and
reachable code/data emerge together from isolated hardware models. Keep each
step regression-locked before replacing the next heuristic. A1 duplicate-image
provenance, A2 preselection enumeration, A3 hypothesis-local state-space
execution, A4 first-class provenance, A5 unified viability, A6 bank-access
completeness, and A7 final evidence comparison are complete; A8 is next.

A3-A6 execution/provenance/viability invariants (completed)
    Every A2 hypothesis is executed independently from every legal RESET state in
    the same mapper-aware fixed-point engine. Known conditions choose one edge;
    unknown conditions fork feasible edges. Hardware input remains unknown rather
    than sampled. Physical ROM provenance flows through supported CPU operations,
    RIOT/cart RAM and generated RAM code, including mapper switches and display
    sinks. A5 viability rejects only hard-dead feasible paths (JAM/KIL/HLT, invalid
    targets/bus accesses); branches are OR nodes and JSR requires callee plus return.
    A6 credits meaningful banks only from viable execution/provenance, while exact
    duplicates and pure fill are explained structurally. N-in-1 applies the same
    execution and completeness rules recursively. These stages produce evidence;
    none chooses the final mapper.

A7 final-comparison invariant (completed)
    A7 consumes the common A3/A5/A6 results directly; it does not rerun a privileged
    legacy candidate set and instruction count is never mapper evidence. Hard A5
    contradictions are removed first. Surviving hypotheses are then narrowed by
    positive evidence in semantic order: a bank switch that preserves a coherent
    continuation, mapper-specific selector activity (including proven generated-RAM
    selectors), direction-correct cartridge-RAM behavior, complete A6 bank access,
    and comparable reset quality. Established explicit/static signatures are only
    late migration priors after execution evidence ties. Indexed/model-dependent
    traffic may not bootstrap a mapper family merely because that hypothetical
    mapper would reinterpret it as a selector. For broad partial-address decoders
    (0840/UA/UASW/0FA0), an unresolved indexed selector forks every feasible
    bank/no-switch hardware continuation instead of guessing or ignoring it.

    If exactly one hypothesis survives a principled comparison, select it and emit
    why every alternative lost. If several remain genuinely indistinguishable,
    report all of them and use exact unknown/raw presentation instead of the old
    size/default winner. The only presentation exception is observationally
    equivalent plain 4K versus one-bank FC with no FC behavior, where ordinary 4K
    code presentation preserves the same observed mapping while the header states
    that mapper identity remains ambiguous. First-class N-in-1 hypotheses obey the
    same rule: an 8IN1/4IN1 or F8/2IN1 tie remains raw unless execution supplies a
    real discriminator; `--container` remains the explicit external-knowledge path.

A8. [ ] Feed exhaustive execution back into code/data presentation
    * Established execution under the selected hypothesis remains authoritative.
      ROM bytes proven to feed executable RAM are code-source data; bytes proven to
      feed GRP0/GRP1 or other consumers are data-source evidence.  Preserve exact
      bytes even when one physical byte has more than one runtime role.
    * Revisit detached island discovery after hypothesis execution is mature: it
      should fill genuinely unreachable presentation gaps, not compensate for an
      execution engine that failed to explore feasible control flow.
    * Regression set must include Congo Bongo's generated F8 selector, the prior
      false-mapper cases that motivated the trust gate, duplicate/padded images,
      all-bank coverage, unknown-input branch forking, and mapper-specific
      read/write hotspot direction.

Weak "nonsense operation string" evidence
-----------------------------------------
Use only a weak signal for instruction sequences whose semantic work is
immediately obliterated; beam-path code may intentionally burn cycles. Prefer
dead-definition/dataflow analysis over byte-string patterns. A definition is
suspicious when all effects are overwritten before use and it had no meaningful
bus/device/mapper side effect. Examples:

* `LDA #$00 ; LDA #$FF` when neither A nor the first N/Z result is observed.
* Back-to-back LDX/LDY/transfers, contradictory flag sets, or ALU/update work
  whose earlier register/flag result is dead before use.
* A pure RAM load immediately replaced before value/flags are used.
* A RAM store overwritten before any feasible read, absent device/mapper semantics.
* `JMP`/branch to the immediately following instruction, or other control-flow
  detours that have no semantic effect except cycles.

Do not call local redundancy nonsense when bus/timing effects may matter:
TIA/RIOT/peripheral/mapper accesses can have side effects; discarded bankswitch
reads still matter; stack/flag/ALU/unofficial operations may be cycle padding.
Near visible-beam/WSYNC activity sharply suppress the penalty. Blanking code can
also burn cycles, so beam knowledge changes weight rather than proving purpose.

Accumulate gently: one dead definition barely matters; several independent
clobbers can lower confidence. Cap the penalty so it never kills a path/mapper.
Hard contradictions remain separate. Proven reachable code stays code; retain
this only as a diagnostic/statistic.

Current direction
-----------------
The mapper-hypothesis execution roadmap is the current analysis priority. A1
through A7 are complete; A8 exhaustive-execution feedback into code/data
presentation is next. The preselection set contains every structurally compatible
ordinary mapper plus first-class N-in-1 topologies before any winner is chosen,
A3 executes every one in isolation, and A7 selects only from shared
contradiction/positive evidence. Unresolved ties are raw rather than inherited
size/default choices. GL implementation remains complete with only real-corpus
closeout pending; CM, DPC+, and the CDF family remain the mapper-specific queue
after/alongside that migration.

When corpus work resumes, prefer one concrete mismatch/failure category at a
time, add a minimal synthetic regression plus the real corpus case, and keep
exact round trip non-negotiable. Do not grow this file with per-ROM victory
narratives; put those in the daily history.
