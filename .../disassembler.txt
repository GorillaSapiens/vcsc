VCSC DISASSEMBLER: DURABLE CONTRACT AND OPEN WORK
=================================================

Purpose
-------
`vcsc-disas` turns an Atari 2600 cartridge image into VCSC `.s26` that
`vcsc-as` can reassemble **byte-for-byte exactly**. Readability and inference are
important, but exact reconstruction wins every conflict. Completed development
history is in `.../context-history/`; the pre-cleanup full roadmap is archived in
2026-08-22.

Durable invariants
------------------
* Never normalize the image. Preserve file length, duplicate banks, inaccessible
  bytes, fill, vector oddities, and trailing preservation bytes exactly.
* Identical input plus identical command line must produce identical `.s26`.
* If semantic interpretation is uncertain, emit exact raw bytes and annotate the
  uncertainty. A zero-instruction result is still a hard analysis failure.
* Physical file position and 6507 runtime address are distinct. Use `.org` for
  physical output and `.rorg`/`.rend` for runtime PC. Preserve encoded mirrored
  addresses when changing them would alter operand bytes.
* A real `JMP ($xxFF)` must remain raw bytes because `vcsc-as` deliberately
  rejects that hazardous NMOS spelling.
* Conditional branches must carry deterministic `.same`/`.cross` timing when
  emitted symbolically; if the one-bank presentation cannot represent the real
  mapper-resolved relative target, keep the original bytes raw.
* Established execution evidence controls mapper/video/controller/hardware
  decisions. Detached speculative islands may improve presentation but must not
  promote mapper hypotheses, Superchip semantics, or execution roots.
* Mapper inference is a hardware-state problem, not merely a file-size/name
  lookup. Keep mapper context separate when following code across selectors.
* Multi-game containers are separate cartridge analyses concatenated in original
  order; no CFG or ROM reference crosses a component boundary.
* The standalone `disassembler/roundtrip.pl` remains the mechanical exactness
  oracle. Stella differential mapper checks are useful evidence, not authority.

Unfinished mapper support
-------------------------
23. [ ] GL mapper
    * Model GameLine's four independently mapped 1K segments and selectors.
    * Track ROM/RAM selection plus RAM read/write direction.
    * Keep modem/PROM control conservative and add real exact-round-trip fixtures.

24. [ ] CM mapper
    * Model CompuMate as ROM/RAM mapping controlled through SWCHA, not a normal
      hotspot mapper.
    * Carry bank-select, RAM-enable, and RAM-direction state; add exact fixtures
      and controller-state transition tests.

25. [ ] DPC+
    * Treat DPC+ as a distinct ARM-assisted format.
    * First recover structural regions and exact 6507-visible control flow; ARM
      analysis may stay conservative/raw until needed.
    * Require real-format exact reconstruction before richer semantics.

26. [ ] CDF / CDFJ / CDFJ+
    * Keep format generations explicit.
    * Start with structural preservation and 6507-visible program-bank flow; add
      ARM/datastream semantics only when they improve reachable-code inference.
    * Require real corpus fixtures, Stella differential checks, and exact round
      trip for every supported generation.

Unfinished analysis correctness
-------------------------------
27. [ ] Finish 6507 interrupt-vector reachability.
    * RESET is the hardware entry. Reachable BRK may promote the IRQ/BRK vector.
    * Remove the remaining unconditional NMI-root behavior; the 6507 has no
      bonded NMI input.
    * Preserve positive BRK-handler coverage while ensuring vector bytes alone do
      not fabricate code in mapper/vector tails.

31. [ ] Finish mapper-context abstract CPU-state precision.
    * Do not merge all abstract A/X/Y/P/ZP state solely by physical byte.
    * Key/merge state by physical location plus mapper context (or equivalent),
      and requeue improved states to a fixed point.
    * 3F may legally select the final physical bank into the lower window; do not
      "solve" context aliasing by forbidding that hardware behavior.

35. [ ] Replace speculative validation caps with a state-keyed fixed point.
    * Use a worklist keyed by physical location, mapper context, and abstract facts
      affecting successors.
    * Merge/widen until the finite abstract state converges; safety exhaustion may
      reduce confidence but must never manufacture a stronger result.

41. [ ] Finish ambiguous multi-game container handling, especially 2IN1.
    * Existing conservative 4IN1/8IN1/32IN1 behavior is the baseline.
    * Do not infer 2IN1 from size alone; require strong structural/database or an
      explicit override path.
    * Analyze each component independently and reconstruct the outer image by
      exact concatenation in original order.

Current direction
-----------------
When corpus work resumes, prefer one concrete mismatch/failure category at a
time, add a minimal synthetic regression plus the real corpus case, and keep
exact round trip non-negotiable. Do not grow this file with per-ROM victory
narratives; put those in the daily history.
