Example directory reorganization
================================

Status
------
Migration is complete through ER13.  ER14 is the next unfinished slice.
The target tree and migration invariants below remain authoritative while the
remaining renderer/video-standard/diagnostic moves are in progress.

Goals
-----
The public `examples/` tree should answer "what am I trying to learn or run?"
rather than expose the historical order in which renderer families were added.
Use these rules:

* `01_basics` is strict: no reusable renderer and no reusable display component.
  It demonstrates basic VCSC/TIA/audio/lifecycle functionality directly.
* `02_components` contains standalone component demonstrations.  Do not add a
  redundant `scores/` directory; score components live directly here.
* `03_controllers` teaches controller input.  Games that happen to use a
  controller do not belong here.
* `04_renderers` is organized first by actual renderer identity.  Scanline count
  (192/181/170/228) is an implementation/composition detail and normally does
  not appear in the path.  `no_score`, `score_above`, `score_below`, and
  `score_above_and_below` describe the visible composition instead.
* Renderer identities remain peers.  In particular `faithful_legacy_player_color`
  is not a subtype of `player_color`; `faithful_legacy_multisprite` is not a
  subtype of `multisprite`; and `all_five_unofficial` is a different renderer
  from `all_five`.  The same rule keeps `player_color_unofficial` separate from
  `player_color`.
* `05_video_standards` exists specifically to compare NTSC/PAL/SECAM behavior.
  It is organized by demonstration first and standard second so the three
  standards are adjacent.
* `06_games` contains finished playable games regardless of which controller
  they demonstrate.  Tanks, Paddleball, and four-player Paddleball belong
  together.
* `07_diagnostics` contains hardware/toolchain diagnostics.  Bankswitching is a
  diagnostic family rather than a peer of renderers/games/components.
* `_common` contains support source shared by multiple public examples and is
  explicitly not a runnable example category.
* Flatten directories whose only purpose is to contain one `01_interactive` or
  similar child.  A leaf example should normally contain its `.c26`, Makefile,
  README, and local assets directly.
* Moving an example is not just a filesystem rename.  Relative includes,
  Makefile `ROOT`, tests, golden metadata, build/install/package smokes, public
  documentation, licensing paths, and example-count/layout assertions must all
  be audited in the same migration slice.

Existing-example mapping
------------------------
The reorganization is intended to preserve every existing runnable example.
The following family-level mapping is authoritative enough to drive the move;
individual source filenames need not be renamed merely because their directory
moves.

* `01_basic/01_blank_screen`, `02_blank_noasm`, `03_ode_to_joy`
  -> `01_basics/`.
* `01_basic/04_score`, `06_wide_score`, `07_big_wide_score`, `08_dual_score`
  -> the corresponding direct children of `02_components/` (`dual_score`
  becomes `three_plus_three_score` as a directory-purpose name).
* `01_basic/14_heart_score/heart_score.c26` -> `02_components/heart_score/`.
  The same current directory also contains the score-above and score-below
  interactive cartridges; those do NOT stay with the standalone component.
  Split them into `04_renderers/player_color/score_above/heart/` and
  `04_renderers/player_color/score_below/heart/`.  This requires splitting the
  current three-target Makefile/README rather than simply moving one directory.
* `01_basic/11_keypad` -> `03_controllers/keypad`; `01_basic/12_drive`
  -> `03_controllers/driving`.
* `01_basic/09_paddleball`, `10_four_player_paddleball`, `13_tanks`
  -> `06_games/`.  They are games, not controller tutorials.
* `01_basic/05_fingerprint` -> `07_diagnostics/6507_fingerprint`.
* `02_faithful_legacy_playercolors` ->
  `04_renderers/faithful_legacy_player_color`.
* `10_faithful_legacy_multisprite` ->
  `04_renderers/faithful_legacy_multisprite`.
* `03_player_color_192` -> `04_renderers/player_color/no_score` plus

* `04_player_color_181` -> the official `player_color` score-above/score-below

* `06_all_five_181` -> the official `all_five` score-above/score-below matrix.

Remaining new examples deliberately required
---------------------------------------------
The joystick and paddle tutorials now exist.  The only still-planned additions
are six `05_video_standards/*/ntsc` cells matching the existing PAL/SECAM
demonstration families: blank, player_color, all_five, all_five_unofficial,
multisprite, and enhanced_multisprite_asymmetric.  These are dedicated
standards-comparison cells even where another NTSC renderer demo already exists
elsewhere.  Share source/support where useful so the comparison does not drift,
but keep the standards matrix explicit.

No other new example is implied by this document.  In particular there is no
planned scoreless `player_color_unofficial` example and no new
`all_five_player_color` score layout beyond its existing centered above/below
examples.

Shared support policy
---------------------
Rename `examples/common` to `examples/_common` and consolidate genuinely shared
support there where doing so removes awkward family-local helper placement.
Likely candidates include the existing fixed-score controls, two-plus-two,
poison, heart controls, player/all-five/multisprite interactive common sources,
`three_plus_three_controls.c26`, the all-five-player-color interactive common
source, and the video-standard multisprite common source.  A helper used only by
one leaf/family may remain local; for example UA's common source belongs with the
UA multi-ROM diagnostic.  `_common` must contain no public runnable cartridge
Makefile.

Migration hazards / required audit
----------------------------------
Every move slice must check at least these classes of coupling before it is
called complete:

* source `include` paths, especially `../../../_common/...` and family-local
  controls;
* each example Makefile's `ROOT`, `VCS_DIR`, `COMMON`, target list, and `play`
  behavior; multi-ROM examples must retain the existing Stella `for`-loop rule;
* root `Makefile` example discovery, bankswitching discovery, release/package
  smoke paths, and installed-toolchain smoke paths;
* `packaging/install.manifest` behavior (the examples tree is copied as a tree,
  but install/release validation may still assert concrete paths);
* tests and fixtures with explicit paths, including assembly allowlist inventory,
  animated-gallery RAM accounting, diagnostic-cart tests, VSYNC/layout checks,
  video-standard layout checks, and source-tree hygiene;
* tests that synthesize a path from a renderer/group name even when they do not
  contain a literal `examples/...` string;
* public documentation in root/driver/Linux/Windows/library/renderer READMEs;
* the animated-sprites directory's CC BY-NC-SA license exception: moving the
  directory must move/preserve the local license and update every statement that
  names the exception path;
* recursively discovered example counts and any assumptions that a leaf is a
  fixed number of directories below `examples/`;
* generated/install-clean behavior and `make play` behavior after relative depth
  changes;
* exact ROM/raster tests should continue to prove that a pure path move did not
  alter cartridge bytes.  If a migration slice changes source organization or
  adds a new example, distinguish that from byte-preserving relocations.

Roadmap
-------
Each item is intentionally scoped to a single roughly 25-minute execution
window.  Do not combine several move families merely because the edits look
mechanical.  After each slice, run the focused tests for the moved family plus
source-tree hygiene/example-build checks appropriate to the change, then package
normally if that slice is the turn's handoff.

[ ] ER14. Move official all_five no-score and centered/basic score leaves.
    * Move the 192 no-score example plus centered/left/right above/below leaves.
    * Update all-five common support and focused raster tests.

[ ] ER15. Finish official all_five score compositions.
    * Move two-plus-two, three-plus-three, poison above/below, plus the existing
      170 score-above-and-below example.
    * Run the complete official all_five example matrix after the move.

[ ] ER16. Move all_five_unofficial as a peer renderer.
    * Move its full 181 above/below matrix plus the existing 170
      score-above-and-below example.
    * Preserve unofficial opcode settings and prove the 170 example was not lost.

[ ] ER17. Move all_five_player_color.
    * Move no-score plus centered score-above/score-below examples under the one
      renderer identity and flatten single-child layers.
    * Move/consolidate its shared interactive helper as appropriate.

[ ] ER18. Move modern multisprite and enhanced multisprite.
    * Move multisprite no-score/score-above/score-below leaves and enhanced
      multisprite no_score_asymmetric.
    * Update renderer docs, shared helpers, raster tests, and standard-wrapper
      references without touching faithful legacy multisprite (already ER9).

[ ] ER19. Re-layout existing PAL/SECAM standards examples.

[ ] ER20. Add first half of the NTSC standards matrix.
