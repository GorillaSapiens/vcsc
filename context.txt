Project goal
------------
Reduce the existing general-purpose N 6502 toolchain to a small C-like language
and toolchain aimed specifically at the Atari 2600/VCS. Compatibility with the
old general-purpose language is not a goal. Features are being removed in
controlled, testable vertical slices.

Settled final-language decisions
--------------------------------
* Target: Atari 2600/VCS using the 6507 CPU.
* All multibyte values are little-endian.
* The only user-visible basic integer types will be:

      int8_t
      uint8_t
      int16_t
      uint16_t

* No float or double.
* No int32_t, uint32_t, or wider integers.
* void remains a special non-value type.
* Pointers are special 16-bit little-endian values.
* Functions retain normal source-level parameters and lexical scope.
* The final ABI has no software argument/local stack.
* Parameters and automatic locals use statically allocated storage.
* A function has one activation record and is intentionally non-reentrant.
* Direct recursion, mutual recursion, callback re-entry, and any other path that
  activates the same function twice must be rejected.
* JSR/RTS still use the 6502 hardware stack for return addresses.
* Function returns:

      void:            no value
      8-bit integer:   A; X unspecified
      16-bit integer:  A low byte, X high byte
      pointer:         A low byte, X high byte

* No function may return a value larger than two bytes.
* Struct, union, and array returns are forbidden even when the aggregate is one
  or two bytes. Use an explicit result pointer.

Completed vertical slices
-------------------------
1. One- and two-byte little-endian integer and pointer returns use A:X.
2. Every fixed parameter of a directly named function is callee-owned symbol
   storage rather than software-stack storage.
3. Function return types are now restricted to void, supported 8/16-bit
   little-endian integers, and 16-bit pointers. The old caller-owned return-slot
   ABI has been deleted.
4. The VCS linker now exposes only $80-$DF as allocatable RIOT RAM and reserves
   $E0-$FF for the 6502 hardware stack. The mirrored $0180-$01FF window is no
   longer modeled as separate physical memory.
5. Every named automatic local and the hidden `$$` return object now has
   function-qualified fixed-address storage. Automatic initializers still run
   whenever control reaches the declaration on each invocation.
6. Every remaining compiler `_pushN` allocation site has been inventoried and
   classified in top-level software_stack_inventory.txt. A regression test
   detects unrecorded additions, removals, or count changes.

Current return ABI
------------------
Relevant code:

    compiler/compile_function.c
        return_type_is_void()
        return_type_is_supported()
        return_type_uses_ax()
        function_uses_ax_return()
        validate_function_return_type()

    compiler/compile_call.c
        direct and indirect call result handling

    compiler/abi_meta.c
        return_void / return_ax metadata

Every function declaration and definition is validated. The compiler rejects:

* aggregate and array returns;
* floating-point returns;
* integers larger than two bytes;
* two-byte big-endian integer returns;
* any other noninteger, nonpointer value return.

Pointers to aggregate or otherwise unsupported pointee types are legal because
the returned value is still a 16-bit pointer.

There is no compiler `return_value` metadata mode and no caller-owned return
storage. A caller that consumes a result may still copy A:X to caller-private
software-stack scratch because the old expression engine expects memory-backed
values. That scratch is not part of the function ABI.

Inside a non-void function, `$$` is the source-level return object. It is a
hidden callee-owned fixed-address symbol. The epilogue loads it into A:X.

Current direct-parameter ABI
----------------------------
Every fixed parameter of a directly named function has a callee-owned symbol.
At a direct call, the caller:

1. reserves one reusable temporary area large enough for the largest argument;
2. evaluates arguments left-to-right;
3. converts each argument in that scratch area;
4. copies it to the corresponding callee parameter symbol;
5. executes JSR;
6. consumes A:X and releases scratch.

The temporary evaluation area still uses the software stack. Parameters do not.
Parameter symbols may be ordinary absolute storage or zero-page storage.

Call-graph and function-pointer rules
-------------------------------------
No function body may be active twice because its parameters, automatic locals,
and return object share one fixed activation record. Compiler and linker
call-graph checks reject same-unit and cross-object cycles, including cycles
through zero-parameter functions.

A plain function pointer contains only a code address and cannot identify the
callee-owned parameter symbols. Therefore:

* taking the address of a parameterized function is rejected;
* parameterized indirect calls are unsupported;
* zero-parameter function pointers still work temporarily;
* function pointers are not yet promised in the final minimal language.

Atari 2600 hardware constraints
-------------------------------
* The VCS has 128 physical bytes of RIOT RAM at $80-$FF.
* $180-$1FF is a mirror of the same physical RAM, not separate stack RAM.
* Static storage and JSR/RTS/PHA/PHP stack use therefore compete for one pool.
* Every outstanding JSR consumes two physical RAM bytes until RTS.
* The 6507 has no usable IRQ or NMI inputs, so asynchronous interrupt re-entry
  is not the normal problem; program-controlled re-entry still is.
* Visible kernels have only 76 CPU cycles per scanline. Calls in kernels will
  eventually require an explicit policy or automatic inlining.

Current VCS RAM model
---------------------
File:

    libraries/vcs/vcs_4k.cfg

The linker now models one physical RIOT RAM pool rather than independent RAM
and CPUSTACK regions. The current conservative partition is:

    $80-$DF   96 bytes available to ZEROPAGE, DATA, BSS, and the
              transitional upward-growing N software stack
    $E0-$FF   32 bytes reserved for the downward-growing 6502 hardware stack

The reserved bytes are mirrored at $01E0-$01FF, where JSR/RTS/PHA/PHP actually
address them through the 6502 stack pointer. They are intentionally absent from
the linker MEMORY list, so ordinary storage cannot be allocated there.

The linker-generated `__stack_top` for the N software stack is therefore $00DF.
This is a fixed provisional reserve; exact call-depth-based sizing remains a
later optimization.

Tests verify both the map and enforcement:

* a VCS link map must show RAM start $0080, size $0060, and stack top $00DF;
* a BSS allocation that would cross into the reserved hardware-stack bytes must
  fail at link time;
* a configuration guard rejects any reintroduced CPUSTACK memory region and
  requires ARGSTACK to share RAM.

Old software-stack machinery still present
------------------------------------------
Top-level software_stack_inventory.txt is the authoritative detailed inventory.
At this snapshot the compiler contains:

    30  emitted `_pushN` allocation sites
    78  emitted `_popN` normal/error cleanup paths

The remaining allocations are classified as:

* retained direct-call argument conversion and A:X consumption scratch;
* retained scalar/pointer expression, conversion, lvalue, switch, and
  initializer scratch;
* conditional aggregate, bit-field, absolute-reference, and runtime-global-
  initializer scratch;
* obsolete variadic, indirect-call, operator-overload, float, wide-integer,
  and arbitrary-endian paths.

There are no remaining `_pushN` sites whose purpose is to allocate ordinary
named automatic locals or `$$`.

The generic test test/software_stack_inventory.test checks the per-file and
whole-compiler emission counts. Any later stack-removal change must update both
the test and software_stack_inventory.txt deliberately.

Test policy
-----------
When a feature is removed:

1. delete positive tests whose purpose is to prove that feature works;
2. keep or add negative tests proving the compiler rejects it cleanly;
3. rewrite tests whose real subject remains useful to use legal types or
   out-parameters;
4. list every intentionally deleted test path in remove.txt.

In this return-restriction slice:

* 7 obsolete compile/codegen positive tests were deleted;
* 28 obsolete E2E positive tests were deleted;
* 6 focused return-contract tests were added;
* useful wide/float/endian arithmetic tests were converted to void functions
  with global/out-value results, because this slice rejects those types only as
  function returns; their complete removal is a later TODO.

Build environment

    /mnt/data/vcsc_toolroot

Required environment:

    export PATH=/mnt/data/vcsc_toolroot/usr/bin:$PATH
    export LD_LIBRARY_PATH=/mnt/data/vcsc_toolroot/usr/lib/x86_64-linux-gnu:${LD_LIBRARY_PATH:-}
    export BISON_PKGDATADIR=/mnt/data/vcsc_toolroot/usr/share/bison

BISON_PKGDATADIR is required because the privately unpacked bison otherwise
looks under the host /usr/share/bison.
