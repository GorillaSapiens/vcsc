If you're not respecting the ABI, you're one segfault away from chaos.

Current transitional function ABI
---------------------------------

This document describes the ABI while the compiler is being reduced for the
Atari 2600. Fixed parameters and named automatic locals use callee-owned
symbols. Ordinary direct calls, truth tests, comparisons, simple fixed-symbol
assignments, casts, absolute-reference conversion, built-in increment/decrement,
compound assignment, pointer/index lvalues, braced and runtime-global
initializers, bit-field helpers, switch expressions, and all builtin operator
families use function/depth-pooled fixed scratch. Compiler source emits no
`_pushN` or `_popN`.

Function returns
----------------

Every legal function return is one of:

* `void`: no returned value;
* one- through four-byte ordinary little-endian integer;
* one-, two-, or three-byte packed-BCD little-endian integer;
* 16-bit pointer.

Functions may not return aggregates, arrays, floating-point values, or other
non-scalar objects. The stock interface and compiler/memory-return ABI expose
ordinary binary integers through 32 bits. `bcd24_t` is also a legal return type.

Inside a value-returning function, `$$` is the source-level return object. It is
an exact-sized hidden callee-owned zero-page symbol named
`function$__return`. `return expr;` writes the converted value to `$$`;
`return;` leaves any value explicitly written there intact. The common epilogue
for every value width is simply:

rts

The callee does not load A, X, or Y with the result. The return-object symbol is
exported with every non-static definition. A separately compiled caller imports
that zero-page symbol only when it consumes the call result.

Before an ordinary direct call, the compiler may lease the caller function's
current depth slot, such as `__vcsc_scratch_0`, when arguments need evaluation
or conversion. The lease is a compile-time choice of a fixed symbol; it has no
runtime pointer and emits no activation/deactivation instructions. Generated
code addresses the selected object directly, for example:

ldy #0
lda __vcsc_scratch_0,y
sta function$value,y
jsr function

If the enclosing expression consumes the value, the caller copies the exact
return width directly from `function$__return` into its destination. No
register preservation and no return-only scratch lease are required. Ignored
return values require no copy.

Scratch remains pooled by function and lexical emission depth for arguments and
other expression temporaries. Sequential uses in one function reuse a slot;
nested uses get deeper slots; different functions get distinct physical symbols
so caller data remains valid during a callee. Each slot is emitted at the
maximum size observed for that depth. Scratch leases are compile-time LIFO
records, and compilation fails if any lease remains live at the end of code
generation.

Function entry has no software-stack prologue. Named automatic locals and the
return object already have fixed symbols. Expression temporaries are addressed
directly through their linker-resolved `__vcsc_scratch_N` symbols. A purpose-
specific `ptr0`/`ptr1` indirect address is prepared only when a dynamic or
out-of-range offset actually requires one.

Reset/startup initializes the 6502 hardware stack, DATA, BSS, and init tables.
There is no runtime frame pointer or software stack pointer. The stock runtime
zero-page workspace is 16 bytes: `arg0`, `arg1`, `ptr0` through `ptr3`, and
`tmp0` through `tmp5`. Division and remainder use a private four-byte BSS
workspace in the `_divNle` archive member, so that storage is linked only when
`/` or `%` is actually used.
The linker reserves two hardware-stack bytes per active source function for JSR
return addresses. If one or more runtime initializer functions are linked, it also
reserves one fixed two-byte allowance because startup preserves its init-table
cursor while calling each initializer.

A, P, X, and Y are caller-clobbered across ordinary function calls. None carries
a language-level return value. Special assembly APIs may document stronger
register contracts, but ordinary VCSC calls do not.

The decimal-mode flag is not part of the call ABI. Startup executes CLD, and
compiler-generated packed-BCD addition/subtraction emits a local SED/CLD pair
around only its ADC/SBC chain. Compiled code therefore enters and leaves normal
expression and call boundaries with decimal mode clear. Inline assembly that
sets decimal mode must clear it before returning control to generated code.

NOTE: If a special-case wrapper needs to preserve both A and P, and wants P
exactly as it was, it must pull P last:

PHP      ; save status
PHA      ; save A
...
PLA      ; restore A (and flags get set from A)
PLP      ; restore original status flags, including N/Z

Direct fixed-parameter ABI
--------------------------

Every non-void parameter of a directly named function has a
callee-owned symbol. Ordinary parameters use BSS-backed absolute symbols;
parameters explicitly assigned to a zero-page memory region use zero-page
symbols. The caller evaluates arguments from left to right and writes each
converted value to the corresponding symbol before JSR.

Parameters may use ordinary binary integers through four bytes and `bcd8_t`,
`bcd16_t`, or `bcd24_t`. Linker-visible ABI
fingerprints distinguish packed-BCD storage from same-sized ordinary unsigned
integers, so separately compiled declarations cannot silently disagree about
the representation.

A direct call therefore places no fixed parameter bytes on the software stack
and allocates no software-stack call frame. Argument conversion uses a live caller-function `__vcsc_scratch_N` lease when needed. Return values are read directly from the callee-owned `function$__return` symbol; scratch belongs to the caller and is not part of the callee ABI.

Every function body owns one fixed activation record containing its parameters,
automatic locals, and return object when present. No function may be active
twice. The compiler rejects direct and mutual cycles inside a translation unit,
and the linker rejects cycles completed across objects.

Function pointers and indirect calls are not part of the VCS ABI. Every call
target is directly named, allowing compiler/linker call-graph analysis to see
every edge. Function-pointer declarators and function names used as values are
compile-time errors, and the `_callptr0` runtime trampoline no longer exists.


Variadic functions
------------------

Variadic functions and callable types are not part of the VCSC language.
The lexer rejects `...` with a direct diagnostic. There is no variadic call
frame, hidden metadata, `va_list`, `va_start`, `va_arg`, or `va_end` ABI.
