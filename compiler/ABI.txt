If you're not respecting the ABI, you're one segfault away from chaos.

Current transitional function ABI
---------------------------------

This document describes the ABI while the compiler is being reduced for the
Atari 2600. Fixed parameters and named automatic locals use callee-owned
symbols. Ordinary direct calls, truth tests, comparisons, simple fixed-symbol
assignments, casts, absolute-reference conversion, built-in increment/decrement,
compound assignment, pointer/index lvalues, braced and runtime-global
initializers, bit-field helpers, switch expressions, and all builtin operator
families use fixed per-site scratch. Compiler source emits no `_pushN` or `_popN`.

Function returns
----------------

Every legal function return is one of:

* `void`: no returned value;
* one-byte integer: A contains the value and X is unspecified;
* two-byte little-endian integer: A contains the low byte and X the high byte;
* 16-bit pointer: A contains the low byte and X the high byte.

Functions may not return aggregates, arrays, floating-point values, or any
value larger than two bytes. All legal multibyte return values are little-endian. The compiler rejects those return
types at the declaration or definition. There is no caller-owned return-slot
ABI or `return_value` metadata mode.

Inside a value-returning function, `$$` is the source-level return object. It is
a hidden callee-owned symbol. `return expr;` writes the converted value to
`$$`. At the common epilogue, the compiler loads the high byte into X when
present, loads the low byte into A, and executes RTS.

Before an ordinary direct call, the compiler assigns the call site
a private fixed BSS symbol such as `__n65_calltmp_0`. For each fixed argument:

; save caller fp on the HARDWARE stack
lda fp+1
pha
lda fp
pha
; redirect fp to fixed call-site scratch
lda #<__n65_calltmp_0
sta fp
lda #>__n65_calltmp_0
sta fp+1
; evaluate and convert the argument through that scratch
; copy it into the callee-owned parameter symbol
; restore caller fp
pla
sta fp
pla
sta fp+1

The caller then saves `fp`, executes JSR, and restores `fp` without destroying
A:X. If the enclosing expression needs a memory-backed result, A:X is copied to
the same fixed call-site scratch and converted into its destination.

The scratch symbol is sized to the greatest temporary depth observed while
compiling any argument at that call site, or to the consumed return width when
larger. Scratch is allocated per call site so nested calls remain safe. It is
not overlaid yet, so this transitional ABI can consume more RAM than necessary.

Function entry has no software-stack prologue. Named automatic locals already have
fixed symbols. An expression site that needs temporary storage redirects `fp` to its
own fixed BSS scratch and restores the caller value through the 6502 hardware stack.

Function epilogue for a value return:

; load high byte of $$ into X for a two-byte result
; load low byte of $$ into A
rts

Function epilogue for void:

rts

Reset/startup still initializes `sp` and `fp` during the transitional runtime.
Compiler-generated code no longer allocates through `sp`; `fp` remains the addressing
base for fixed scratch. The target language now has only one- and two-byte integers,
but a few runtime services (notably generic division and `_sbrk`) still reference
`sp`; removing that residual runtime stack state is a separate cleanup step.

A, P, X, and Y are caller-clobbered across ordinary function calls, except that
A and possibly X carry the function result on return. Callers must assume a
callee may freely overwrite all registers before producing that result unless
an API explicitly documents stronger guarantees.

NOTE: If a special-case wrapper needs to preserve both A and P, and wants P
exactly as it was, it must pull P last:

PHP      ; save status
PHA      ; save A
...
PLA      ; restore A (and flags get set from A)
PLP      ; restore original status flags, including N/Z


Direct fixed-parameter ABI
--------------------------

Every non-void parameter of a directly named function has a
callee-owned symbol. Ordinary parameters use BSS-backed absolute symbols;
parameters explicitly assigned to a zero-page memory region use zero-page
symbols. The caller evaluates arguments from left to right and writes each
converted value to the corresponding symbol before JSR.

A direct call therefore places no fixed parameter bytes on the software stack
and allocates no software-stack call frame. Argument conversion and optional
A:X consumption use the call site's fixed `__n65_calltmp_N` symbol. That scratch
belongs to the caller and is not part of the callee ABI.

Every function body owns one fixed activation record containing its parameters,
automatic locals, and return object when present. No function may be active
twice. The compiler rejects direct and mutual cycles inside a translation unit,
and the linker rejects cycles completed across objects.

Function pointers and indirect calls are not part of the VCS ABI. Every call
target is directly named, allowing compiler/linker call-graph analysis to see
every edge. Function-pointer declarators and function names used as values are
compile-time errors, and the `_callptr0` runtime trampoline no longer exists.


Variadic functions
------------------

Variadic functions and callable types are not part of the VCSC language.
The lexer rejects `...` with a direct diagnostic. There is no variadic call
frame, hidden metadata, `va_list`, `va_start`, `va_arg`, or `va_end` ABI.
