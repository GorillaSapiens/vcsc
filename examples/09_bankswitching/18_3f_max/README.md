# Maximum-size 3F diagnostic

This is the stress version of the Tigervision 3F PASS/FAIL diagnostic. It builds
the maximum VCSC/Stella 3F image: 256 physical 2K banks, or 512K total. Physical
banks 0 through 254 are selectable in the lower `$1000-$17FF` window; bank 255
is the fixed `$1800-$1FFF` startup bank.

The self-test executes every ordered source/destination pair among the 255 lower
banks: 255 x 255 = 65,025 calls. Same-bank pairs use direct JSR. Cross-bank pairs
use VCSC's real generic 3F descriptor trampoline through a seven-byte inline-call
stub copied into RIOT RAM, which keeps the complete matrix small enough to fit in
each 2K source bank. Every lower bank also calls the fixed bank once, and the
fixed bank calls every lower bank once, for 65,535 counted target calls total.

Each destination validates that the requested physical bank actually arrived.
After every cross-bank return, bank-specific code verifies that the original
source bank was restored. The diagnostic also checks 6507 hardware-stack balance
for lower-bank sweeps and fixed-bank calls.

After the torture completes, the cartridge uses the standard bankswitching
diagnostic display: big wide `pass` or `FAIL` on the first line and exactly
`3F max` in the small six-glyph font on the second line. A failure is sticky and
indicates a wrong target, wrong source restoration, stack imbalance, or incorrect
final call count.

The test is intentionally expensive compared with the ordinary 3F diagnostic.
In Stella, force the cartridge type if necessary:

```sh
stella -bs 3F 3f_max_diagnostic.bin
```

The committed `3f_max_torture_*.s26` files are generated by `make_torture.pl`; normal
builds do not require Perl. `make torture` regenerates them when changing the
torture algorithm. `make fonts` likewise regenerates the committed display-font
subsets.

## Progress display

The exhaustive matrix is resumable. While it runs, the cartridge keeps a normal
262-scanline NTSC frame on screen using the blue background from
`01_basic/01_blank_screen`. The big status line reads `wait ` followed by a
spinner cycling `/`, `-`, `\`, `|` every 15 frames (one quarter second). Torture
work is limited to VBLANK and overscan batches; after all 65,535 calls complete,
the display switches to the normal PASS/FAIL result.

The big WAIT and PASS/FAIL glyph bytes are generated from the committed font
subsets and embedded in physical banks 253 and 254 by `make_torture.pl`, keeping
the common lower-bank call entry points at `$1000` and `$1100`.
