# Pristine upstream Atari 2600 BASIC 1.9 player-color oracle

This directory contains the external gold-standard cartridge for the retained
legacy player-color profile. It was built from an untouched checkout of
upstream Atari 2600 BASIC tag `v1.9`, commit
`1cefae05151da014467a0ecfcbacee6847d61404`, using the stock native compiler
and include files plus DASM 2.20.14.1.

Files:

* `faithful_legacy_playercolors.bas` is the complete upstream BASIC source.
* `faithful_legacy_playercolors.bin` is the exact 4096-byte cartridge image.
* `faithful_legacy_playercolors_stella_7.0.png` is a headless Stella 7.0
  reference capture using the software renderer, standard palette, and no TV
  effects.

The source defines `playercolors` and `player1colors` directly instead of using
`set kernel_options playercolors`. Upstream BASIC 1.9 rejects that setter by
itself even though its shipped standard kernel contains and assembles the
corresponding conditional branches. No compiler, include, or assembler source
was patched.

The order of the source is significant. The stock header aliases the two-byte
player color pointers over missile state:

```text
player1color = missile1height/missile1y = $87/$88
player0color = missile0height/missile0y = $90/$91
player0colorstore = missile0x = $82
```

The disabled-missile initialization therefore appears before the
`player0color:` and `player1color:` declarations. Those declarations install
the final color-table pointers. Moving the missile height/Y assignments after
the color declarations destroys both pointers, producing black sprites even
though the graphics bytes remain intact.

Clean-room reproduction command sequence:

```sh
make LEX=flex
export bB="$PWD"
export PATH="$PWD:$PATH"
ln -s /path/to/dasm dasm
./2600basic.native.sh faithful_legacy_playercolors.bas
```

A second extraction and build from the supplied pristine archive reproduced the
binary byte for byte. Headless Stella 7.0 renders both players in their intended
row colors. The runtime regression verifies all eight bitmap rows for P0 and P1,
two raw scanlines apart as required by the stock two-line kernel, together with
the exact row-color writes.

This ROM is deliberately not generated by VCSC and does not depend on the
retained in-tree kernel copy. The repaired VCSC template and separately linked
retained-source audit now match it positively: the comparator observes the same
1,230 visible TIA events and 42 stable 20,064-cycle/264-raw-line frames per ROM.
That result depends on preserving the stock RAM overlays, RAM-backed playfield,
zero-page-indexed playfield reads, source-order sprite tables, and the original
branch page-cross pattern.
